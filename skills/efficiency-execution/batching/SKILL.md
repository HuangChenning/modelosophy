# 批处理 Batching

## 这是什么

**批处理**：把性质相似的任务（邮件、审批、报销、消息回复）集中到少数固定窗口一次做完，而不是随到随做。核心收益是减少上下文切换；代价是单件延迟上升——需显式权衡。

它是**任务归类与时段合并**，不是看板拉动政策，也不是优先级排序本身。

## 什么时候用

- "邮件和消息打断整天"
- "批处理 / 合并同类 / 固定回复窗口"
- 行政与浅工作吞噬深度时间

**不要**当主模型：

- 限制同时进行中的工作项 → [`wip-limits`](../wip-limits/SKILL.md) / [`kanban`](../kanban/SKILL.md)
- 两分钟内可清掉的琐事规则 → [`two-minute-rule`](../two-minute-rule/SKILL.md)
- 日历整块主题安排 → [`time-blocking`](../time-blocking/SKILL.md)

## 怎么用（执行步骤）

1. **列出高频打断源。** 邮件、IM、审批、报销等；标出「可延迟」与「不可批」类。
2. **设批处理窗口。** 如每日 2–3 次×20–40 分钟；窗口外静音通知。判据：窗外是否仍忍不住打开。
3. **同类同批。** 一批只做一类；批内可再用清单加速。
4. **定义 SLA。** 「24 小时内回复」等服务水平，避免批处理变失联。
5. **紧急通道例外。** 真正紧急可打断；事后记入例外清单，防止例外变常态。
6. **复盘切换次数。** 一周后看打断是否下降；若延迟伤害客户，缩短批间隔而非取消批。

## 例证

**客服班次**：每小时集中回一次非紧急工单——揭示吞吐与延迟权衡。

**个人邮箱**：早晚两批——揭示保护深度上午。

## 什么时候不适用（边界）

- **秒级 SLA / 安全告警**：不可批。
- **批次过大导致库存浪费**：精益视角下过大批量有害 → [`lean-thinking`](../lean-thinking/SKILL.md)。
- **创意探索需即时捕捉**：先快速记下，再批处理整理。

## 常见误用

- **把一切都批到周五**：延迟爆炸 → 提高频次。
- **批内继续切换三类事**：失去批义。
- **用批处理逃避重要难事**：先 [`eat-the-frog`](../eat-the-frog/SKILL.md)。
- **无 SLA 的静音**：变成失联。

## 相关模型

- **与[时间块](../time-blocking/SKILL.md)**：批处理窗口常落成日历块。
- **与[两分钟法则](../two-minute-rule/SKILL.md)**：≤2 分钟且在批窗外出现 → 可立即清；其余进批。
- **与[WIP 限制](../wip-limits/SKILL.md)**：批处理管「同类合并」；WIP 管「同时开多少」。
- **与[精益思维](../lean-thinking/SKILL.md)**：警惕过大批量的等待浪费。
- **与[帕累托法则](../../systems-classic-effects/pareto-principle/SKILL.md)**：只互链——先批真正高频的 20% 打断源。
