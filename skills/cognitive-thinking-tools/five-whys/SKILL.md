# 5Why 分析法 Five Whys

## 这是什么

**5Why**：对一个可观察的问题（症状），反复追问「为什么会发生」，把每一层答案当作下一层的前提，沿**因果链**下钻，直到找到值得动手改的原因（常称根因），再设计对策并验证。

它来自丰田生产系统（Taiichi Ohno 等）的现场改善习惯：问题停在「人没注意 / 运气不好」通常不够；要问到流程、标准、设计或系统条件。**「5」是经验深度，不是魔法数字**——有时 3 层够用，有时要 7 层；停点判据是「再问下去不再改变可执行对策」。

5Why ≠ 5W1H（Who/What/When/Where/Why/How）：后者补全叙事要素；本模型专做**因果下钻**。

## 什么时候用

用户出现以下意图时启用本 Skill：

- "出了问题，想找根因，不要只治标"
- "同样故障/客诉反复出现"
- "5Why / 五个为什么 / 为什么的为什么"
- 事故复盘、质量问题、流程失效，需要一层层追因果

**不要**在以下情况套用本模型：

- 用户要补全「谁在何时何地做了什么」→ [`five-w-one-h`](../../thinking-models/five-w-one-h/SKILL.md)
- 用户要按证据标准审整段论证质量 → [`critical-thinking`](../critical-thinking/SKILL.md)
- 用户要从硬约束重建方案、挑战行业惯例 → [`first-principles`](../first-principles/SKILL.md)
- 用户要找系统吞吐瓶颈（约束资源）→ [`theory-of-constraints`](../theory-of-constraints/SKILL.md)
- 需要并行多因、多路径（鱼骨式发散）时，5Why 单链不够，应先发散再对主链下钻

## 怎么用（执行步骤）

1. **钉死可观察的问题陈述。** 写成一句可验证的事实句（含时间/范围），禁止写成评价（「服务太差」→「上周三客户 A 因缺货取消订单」）。判据：外人能否核对是否发生。
2. **写第 1 个 Why：直接导致该症状的近因。** 答案必须是另一件可观察事实或可检验机制，禁止「不重视」「心态不好」等无法对策化的标签。判据：若该近因消失，症状是否合理消失？
3. **对上一层答案再问 Why，形成链。** 每层一行：`Why_n → 因为…`。每层检查：是因果还是相关？是否跳层（把政策直接接到一次操作失误）？若出现分叉，记下旁支，**先选一条主链**走完。
4. **决定停点（根因候选）。** 停在同时满足：(a) 团队能干预；(b) 干预后可预期减少复发；(c) 再问 Why 只会得到「因为宇宙熵增」类无行动信息。可标「系统/设计/标准/培训/供应商」等类别，但类别不是停点本身。
5. **把根因变成对策 + 验证。** 每条对策对应一个根因；写「怎样知道改有效」（计数器、抽检、复发窗口）。若对策只能压症状、根因仍在，回到第 3 步。
6. **对照检查：是否问错了树。** 若现场数据否定主链，换旁支或承认多因并行；禁止为了凑满五次而编故事。

## 例证

**丰田式机床故障链（经典教学例）**：机器停了 → 过载跳闸 → 轴承润滑不足 → 油泵未泵够油 → 泵进油口滤网堵了金属屑 → **滤网为何有屑？** 可能落到防护设计/维护标准。揭示的是：停在「换保险丝」是治标；下钻到可改的设计/维护层。

**客服「态度差」复盘**：投诉「态度差」→ 客服打断客户 → 系统超时强制结案 → SLA 只考核通话时长 → 根因候选是指标设计。揭示：表面「人的问题」常落在**激励与系统约束**；对策应改指标/工具，而非只培训微笑。

**（局限提醒）**：单链 5Why 容易「一条故事讲到底」并忽略交互原因；高风险事故应配合多因分析、时间线与证据，而不是仪式性问满五次。

## 什么时候不适用（边界）

- **多因、非线性、反馈主导**：单链会假精确；改走系统/回路视角（如 [`systems-thinking`](../../systems-classic-effects/systems-thinking/SKILL.md)）。
- **证据不足却硬编因果**：没有数据时，5Why 会变成合理化叙事；先收集事实。
- **归责文化**：若每层 Why 都变成「怪某人」，模型失效——应追流程与条件，而非羞辱。
- **创新设计问题**：不是「故障为何发生」，而是「如何发明新解」→ [`triz`](../triz/SKILL.md) 或 [`first-principles`](../first-principles/SKILL.md)。

## 常见误用

- **凑满五次**：机械问五遍 → 以停点判据为准，次数可变。
- **Why 变成 Who**：每层点名背锅 → 改写为条件/标准/设计缺陷。
- **把相关当因果**：「那天换了班所以坏了」→ 要求机制或对照证据。
- **与 5W1H 混淆**：要新闻要素清单 → [`five-w-one-h`](../../thinking-models/five-w-one-h/SKILL.md)。
- **停在不可行动层**：「因为人性」→ 继续问到可改杠杆，或承认范围外。

## 相关模型

- **与[5W1H](../../thinking-models/five-w-one-h/SKILL.md)**：**硬区分。** 5W1H = 补全 Who/What/When/Where/Why/How 信息框；本模型 = 沿 Why 因果链下钻根因。用户说「把事情说清楚」走 5W1H；「为什么反复出问题」走本模型。
- **与[第一性原理](../first-principles/SKILL.md)**：第一性原理丢掉惯例、从硬约束重建；5Why 在既有故障/失效上向下追因。用户说「行业都这样但未必对」走第一性；「这次事故根因」走 5Why。
- **与[批判性思维](../critical-thinking/SKILL.md)**：批判性思维评估论证与证据标准；5Why 产出的因果链本身要接受证据检验，可连用。
- **与[TOC 约束理论](../theory-of-constraints/SKILL.md)**：TOC 找系统吞吐瓶颈；5Why 找具体失效的因果根因。瓶颈管理走 TOC；单点故障复盘走 5Why。
- **与[假设检验](../hypothesis-testing/SKILL.md)**：5Why 提出根因假设后，应用可证伪观察验证，避免「故事很圆」。
- **与[MECE](../mece/SKILL.md)**：多因并存时先 MECE 分桶，再对主桶做 5Why，避免假单因。

## 记忆钩子

症状不是根因；问到**能改且能验**为止——次数不重要。
