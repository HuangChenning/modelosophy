# 奥兹原则 The Oz Principle

## 这是什么

**奥兹原则（The Oz Principle）**：借用《绿野仙踪》隐喻——出路不靠巫师魔法，而靠角色承担责任——提出 **Above the Line** 问责：面对结果差距时，走 **See It → Own It → Solve It → Do It**（看见事实、拥有问题、求解方案、付诸行动）；**Below the Line** 则是否认、指责、借口、等待与「无助」循环。

在决策类中的用法：不确定性不是放弃选择的许可证；**把可控部分收回应决断与实验**，同时诚实标出不可控约束。

## 什么时候用

- "奥兹原则 / Above the Line / 问责"
- "总在等上级/别的部门，事情不动"
- "复盘变成甩锅大会，想拉回行动"
- 执行卡死、责任扩散、受害者叙事主导的团队决策

**不要**当主模型：

- 需要结构化四步事实复盘 → [`after-action-review`](../after-action-review/SKILL.md)（可嵌奥兹语气）
- 批准前挖失败模式 → [`pre-mortem`](../pre-mortem/SKILL.md)
- 系统瓶颈在别处 → [`theory-of-constraints`](../../cognitive-thinking-tools/theory-of-constraints/SKILL.md)
- 用问责掩盖资源不足或有毒文化 → 先修系统与安全

## 怎么用（执行步骤）

1. **划线诊断。** 列出当前语言：指责、借口、等待、否认 vs 事实与选项。判据：Below 语句占比过高则启动本框架。
2. **See It：看见。** 只陈述可验证事实与数据缺口；禁止动机审判。写下「我们拒绝看见的是什么」。
3. **Own It：担当。** 明确「我对结果的哪一段负责」——含协作界面；不是背全锅，是收回能动性。
4. **Solve It：解决。** 生成 ≥2 个可行选项（含缩小范围、升级请求、实验）；链快速试错/可逆门。
5. **Do It：行动。** 选定项 + 时间盒 + 成功标准；写入决策日志；到期 AAR。
6. **护栏。** 检查是否用「担当」压迫无权者；系统障碍升级而非道德化。

## 例证

**跨部门项目**：互等「对方先动」；Above the Line 后各方写下可独立推进的最小切片并对齐接口。揭示：问责是**收回局部控制权**。

**销售未达标**：Below=市场差/产品差；Above=可改话术实验与管道消毒。揭示：与快速试错连用。

**错误用法**：管理层只讲 Own It 不给资源 → 假问责，破坏信任。

## 什么时候不适用（边界）

- **人身安全/违法指令**：拒绝执行优先于「担当」。
- **严重心理安全缺失**：先建立安全再谈公开 Own It。
- **替代战略分析**：问责不产生市场定位。

## 常见误用

- **变成压责话术**：忽略权限与约束。
- **与 AAR 等同**：AAR 是会议工艺；奥兹是责任姿态与四步能动性。
- **否认外部冲击**：See It 包含外部事实，不是假装全能。
- **停在鸡汤**：无 Do It 时间盒。

## 相关模型

- **与[复盘四步法](../after-action-review/SKILL.md)**：AAR 提供事实对照结构；奥兹确保参与者停在线之上把改进做完。可连用。
- **与[决策日志](../decision-journal/SKILL.md)**：Do It 的承诺写入日志，防口头担当。
- **与[快速试错](../rapid-experimentation/SKILL.md)**：Solve/Do 常落地为实验序列。
- **与[事前验尸](../pre-mortem/SKILL.md)**：验尸合法化报忧（See It）；奥兹防止验尸后无人 Own。
- **与[可逆与不可逆决策](../reversible-irreversible/SKILL.md)**：担当不等于对单向门蛮干；匹配审查重量。

## 记忆钩子

线之上四步：**看见 → 担当 → 解决 → 行动**；线之下是等巫师——而巫师往往不来。
