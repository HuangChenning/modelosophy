# 敏捷迭代 Agile Iteration

## 这是什么

**敏捷迭代**：在短固定周期（迭代/Sprint）内计划、开发出**可检视的工作增量**，再基于反馈调整下一步；强调响应变化、客户协作与工作软件（或等价可验证产出）优于大而全的前期文档与合同对抗。

本 Skill 抓**迭代节奏与增量**，不绑定某公司认证教条。

## 什么时候用

- "需求不确定，怕一次做完做错"
- "敏捷 / Sprint / 迭代交付"
- 产品与软件类团队节奏重建

**不要**当主模型：

- 只要可视化流与 WIP → [`kanban`](../kanban/SKILL.md)
- 识别七大浪费与价值流 → [`lean-thinking`](../lean-thinking/SKILL.md)
- 项目网络工期 → [`critical-path`](../critical-path/SKILL.md)

## 怎么用（执行步骤）

1. **定迭代长度（1–4 周常见）并冻结周期边界。** 周期内目标清晰；中途加塞需显式权衡。
2. **选本迭代可演示增量。** 「完成」定义写清（DoD）；禁止只有会议没有增量。
3. **每日同步阻碍（短）。** 目的是暴露阻塞，不是状态演讲。
4. **迭代末演示+回顾。** 演示对用户/代理用户；回顾改一条流程。
5. **根据学习重排待办。** 拥抱变更在**迭代边界**，而非无序插入。
6. **度量 burndown/吞吐量仅作辅助。** 禁止为了好看曲线牺牲质量。

## 例证

**产品 MVP 双周演示**：每迭代可点开的功能——揭示增量降低错方向成本。

**伪敏捷**：每天站会但三月无发布——揭示缺增量。

## 什么时候不适用（边界）

- **完全已知、强关键路径交期**：传统计划+关键路径可能更合适。
- **无法切片的一次性物理工程**：需改切片策略或混合模型。
- **合规要求完整前置文档**：在约束内做微迭代，不装纯敏捷。

## 常见误用

- **仪式驱动**：会开全无增量。
- **迭代内无限加塞**：毁节奏。
- **与看板对立宗教战**：可组合。
- **敏捷=不写文档**：关键决策仍需记录。

## 相关模型

- **与[看板](../kanban/SKILL.md)**：时间盒 vs 流动；可混合。
- **与[精益](../lean-thinking/SKILL.md)**：精益减浪费；敏捷管不确定性迭代。
- **与[PDCA](../pdca/SKILL.md)**：每个迭代是一次 PDCA。
- **与[OKR](../../strategy-competition/okr/SKILL.md)**：OKR 定结果；迭代交付逼近。
- **与[第二曲线](../../strategy-competition/second-curve/SKILL.md)**：战略换曲线后，用迭代验证新引擎，而非一次押满。

## 记忆钩子

短周期交出**可检视增量**，再适应——不是把瀑布切成两周开会。
