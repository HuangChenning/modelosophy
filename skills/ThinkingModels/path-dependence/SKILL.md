# 路径依赖 Path Dependence

## 这是什么

路径依赖指：后续选择的可行集与相对收益，被**历史路径**塑造；早期偶然或细小差异可经自我强化被放大，导致锁定（lock-in）。狭义常指技术/制度因报酬递增而自我强化；广义说“历史重要”，但分析上要指出具体强化机制，否则不可证伪。

常见强化：规模经济、学习效应、协调/网络效应、适应性预期、既得利益。结果不一定是最优——QWERTY 键盘争论的核心是：**效率标准下的次优也可能因协调成本存活**。

## 什么时候用

- 标准、架构、组织惯例明明别扭却换不掉；
- 讨论“重新选一次还会不会选它”；
- 用户直接说路径依赖 / 锁定 / lock-in。

**不要**当主模型：仅因已花钱不甘心（沉没成本）；只要排本周任务（艾森豪威尔）；只画存量流量（可先系统思维，但锁定故事用本模型）。

## 怎么用（执行步骤）

1. **还原关键分叉点。** 过去哪个选择缩小了今天的菜单？写出当时的可行替代。
2. **点名强化机制。** 是网络协调、培训沉淀、互补品生态、监管认证，还是内部政治租金？至少标一个可检验机制。
3. **估计切换成本与谁承担。** 锁定常因成本落在切换发起者、收益却分散。
4. **区分“还优”与“仅因锁定而存”。** 对照：若无历史包袱的新进入者会选什么？若他们也不选旧路径，更可能是真优；若只老玩家死守，倾向锁定。
5. **设计解锁，而非只叹息。** 过渡层、双轨、补贴早期采用者、强制互联标准——把协调问题显式化。与局部/全局最优的“护栏下坡”连用。

## 例证

**键盘布局争论（QWERTY）**：经典课堂案例；学术上对“是否严重次优”有争议，但阐明了**协调与互补技能**可维持标准。使用时避免当成“一定是最差锁定”的铁证，而当作机制说明。

**企业遗留架构**：核心库被几十个系统依赖，迁移的协调成本高于局部优化。揭示组织版报酬递增。

**城市交通与能源基建**：早期路线/管线选择塑造几十年后的排放与拥堵选项集。

**（原书卡片）自我强化列表**：规模经济等五因子可用；勿把一切惯性都叫路径依赖——无强化机制的“懒得改”更像习惯或沉没成本。

## 什么时候不适用（边界）

- **无报酬递增的普通习惯**：用行为设计/福格，不必上制度锁定理论。
- **不可逆物理约束**：那是硬约束（第一性原理），不是历史偶然放大。
- **故事不可证伪**：“都是因为历史”而指不出机制时，降级为待查假说。

## 相关模型

- **与[局部/全局最优](../local-global-optima/SKILL.md)**：局部峰是现象；路径依赖常解释山谷深度（切换成本结构）。
- **与[沉没成本](../sunk-cost/SKILL.md)**：沉没是已付不可收回；路径依赖是未来协调/网络仍奖励旧路径。
- **与[系统思维](../systems-thinking/SKILL.md)**：增强回路是机制语言；本模型强调历史分叉与锁定政治。
- **与[飞轮](../flywheel/SKILL.md)**：飞轮是有意设计的增强闭环；路径依赖也可以是无意甚至有害的闭环。
