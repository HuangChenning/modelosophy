# StoryBrand SB7 框架

## 这是什么

**SB7** 是一套**品牌/整份文档级别**的叙事定位框架：把客户设为故事主角，品牌设为向导，按七段组织信息。

| 段落 | 含义 | 判据 |
|---|---|---|
| **Character** 角色 | 具体的目标客户 + 想要什么 | 一句话，能把这类客户和相邻客户群区分开 |
| **Problem** 问题 | 外部问题（可见障碍）+ 内部问题（这带来的感受）+ 哲学问题（为什么这事重要） | 三层缺一不可 |
| **Guide** 向导 | 品牌以同理心 + 实证权威出现，而非主角 | 必须同时有"感同身受"和"可验证的能力证明" |
| **Plan** 计划 | 通常 3 步的简单路径 | 降低感知风险和认知负担 |
| **Call to Action** 行动号召 | 直接 CTA（立即购买/预约）+ 过渡 CTA（低摩擦选项） | 两级都要有 |
| **Avoid Failure** 避免失败 | 不行动的真实后果 | 篇幅/情绪强度不超过 Success，克制真实 |
| **Success** 成功 | 选择后的具体、可想象的生活/工作图景 | 具体到画面而非空洞形容词 |

它由 Donald Miller 在《Building a StoryBrand》(2017) 中系统化，首版销量超百万册，此后经 StoryBrand 组织的工作坊和大量顾问机构的应用实践持续传播。

它的核心机制是**地位反转**：多数品牌习惯把自己写成故事主角（"我们如何创立、我们的使命"），SB7 要求把主角让位给客户，品牌退居"帮助主角完成任务的向导"（类比《星球大战》里 Luke 是主角，Yoda 是向导）——这解决的是**整份材料的定位混乱**，而不是某一段文案该怎么写。

## 什么时候用

- "帮我理清品牌故事/定位怎么讲"
- "官网首页/宣传手册整体叙事骨架怎么搭"
- 直接说 StoryBrand / SB7 / 客户是主角品牌是向导
- 内部语言太多、术语堆砌，读者搞不清"这跟我有什么关系"

**不要**当主模型：

- 用户要写某一段具体的广告/朋友圈/落地页短文案 → [`pas`](../pas/SKILL.md)
- 用户要讲清某一个具体功能的价值 → [`fab`](../fab/SKILL.md)
- 用户要做市场/定价/渠道预算等资源分配决策 → SB7 只管叙事定位，不管资源分配
- 面向深度技术、采购主导的 B2B 决策场景 → SB7 需配合详细规格书/技术文档，不能替代

## 怎么用（执行步骤）

1. **写 Character：一句具体的目标客户画像 + 他们想要什么。** 判据：这句话是否能把目标客户和相邻客户群区分开（例如"想降低人为失误导致数据泄露风险的安全负责人"，而不是笼统的"企业客户"）。
2. **写 Problem：外部/内部/哲学三层都要写，缺一不可。** 外部＝看得见的障碍；内部＝这带来的感受（焦虑/疲惫/没面子）；哲学＝为什么解决这件事本身值得（更大的信念）。判据：只写外部问题会让信息显得冷冰冰、缺乏共鸣，必须补全内部层。
3. **写 Guide：先给一句同理心陈述，再给一条可验证的权威证明。** 判据：这段话的主语是不是持续在说"我们/我们的使命/我们如何创立"？如果是，说明把自己写成了主角，要重写成"我们理解你的处境（同理心）+ 我们已经帮 N 个客户做到过 X（权威证明）"。
4. **写 Plan：给一条通常 3 步的简单路径。** 判据：客户看完是否清楚"接下来具体做什么、按什么顺序"，而不是一段模糊的服务介绍。
5. **写 Call to Action：一个直接 CTA（立即购买/预约演示）+ 一个过渡 CTA（下载资料/免费试用等低摩擦选项）。** 判据：还没准备好直接购买的读者，是否也有一个可以点的下一步？只设一个高门槛 CTA 会流失大量未准备好的潜在客户。
6. **写 Avoid Failure：讲清不行动的真实后果，篇幅和情绪强度不超过 Success 部分。** 判据：这个后果是否真实可信、可以举证，而不是为了吓人而夸大；如果读起来比 Success 部分更长、更煽情，说明过度使用了恐惧，要收窄。
7. **写 Success：具体到画面，而不是形容词堆砌。** 判据：读者能否在脑中想象出"选择后的一天/一个场景"，而不是只看到"更高效""更放心"这类空话。

## 例证

**Donald Miller《Building a StoryBrand》(2017)**：把叙事学（约瑟夫·坎贝尔"英雄之旅"的商业化简版）系统化为七段可复制结构，首版销量超百万册，此后通过 StoryBrand 官方工作坊持续培训数千家企业的营销负责人，是把"客户为主角"这一朴素直觉变成可执行方法论的关键节点。

**网络安全 SaaS 公司应用案例（Umbrex 顾问案例）**：Character「想降低人为风险导致数据泄露的安全负责人」→ Problem 外部「员工点击钓鱼链接」+ 内部「CISO 感到暴露和疲惫」→ Guide「2,400 名客户、6 个月内事件减少 41%、ISO 27001 认证」→ Plan「7 天内评估风险 → 上线自适应微培训 → 每月报告进展」→ Success「更少事件、更平静的审计、更低成本」——应用后首页到演示转化率从 1.6% 提升到 3.3%，销售周期缩短 18%。揭示七段结构不是空谈叙事，而是能直接映射到可衡量的转化提升。

## 什么时候不适用（边界）

- **市场/定价/渠道预算等资源分配决策**：SB7 只管"信息怎么组织表达"，不管"钱该往哪投、卖给谁、定什么价" → 这类决策需要独立的战略/财务框架，不要指望 SB7 给出答案。
- **深度技术、采购主导的 B2B 场景**：技术评审委员会需要详细规格、参数对比，单靠叙事骨架无法通过技术评审 → SB7 用于统一对外叙事，但必须配合详细技术文档，不能替代。
- **单篇短文案的具体写法**：SB7 不回答"这条广告的第一句话怎么写"这种颗粒度的问题 → 那是 [`pas`](../pas/SKILL.md) 或 AIDA 的职责范围，SB7 提供的是它们可以嵌套进去的整体骨架。
- **一次性填完就归档**：把 BrandScript 填完锁进文件夹、不渗透到实际官网/手册/销售话术里，等于没做 → SB7 的价值在于持续应用到所有对外材料，而非一次性文档产出。

## 常见误用

- **品牌把自己写成主角**：段落主语持续是"我们的使命/我们如何创立" → 回到步骤 3，改写成同理心 + 权威证明，把主角让给客户。
- **Problem 只写外部障碍，漏掉内部感受和哲学意义**：信息显得冷冰冰、没有共鸣 → 回到步骤 2，补全三层。
- **只设一个高门槛 CTA**：还没准备好购买的读者无路可走，白白流失 → 回到步骤 5，补一个低摩擦的过渡 CTA。
- **过度渲染 Avoid Failure，篇幅盖过 Success**：读者感到被恐吓而非被引导，产生抵触（fearmongering triggers reactance）→ 回到步骤 6，收窄失败陈述，把篇幅和情绪重心放回 Success。
- **机械套用七段模板、毫无品牌个性**：读起来和其他用了 SB7 的品牌千篇一律 → 七段是骨架，具体措辞和细节仍需体现自身风格。
- **与 PAS/FAB 混淆，颗粒度用错**：拿 SB7 去决定一句广告文案怎么写，或拿 PAS 去决定整个品牌怎么定位 → SB7 管整份材料的骨架，PAS 管单篇文案的情绪钩子，FAB 管单个功能的价值翻译，三者颗粒度不同、可以嵌套但不能互相替代。

## 相关模型

- **与[PAS](../pas/SKILL.md)**：**硬区分颗粒度。** SB7 决定整个品牌/文档的定位骨架（七段），PAS 决定单篇短文案的情绪驱动结构（三段）。可以嵌套：用 SB7 定好 Character/Problem/Guide 等骨架后，某一段落（比如落地页开场）可以用 PAS 写成具体钩子。用户说"品牌故事/官网/宣传手册整体叙事"→ SB7；说"这一段广告/朋友圈怎么写"→ PAS。
- **与[FAB](../fab/SKILL.md)**：SB7 的 Plan/Success 段落里经常需要讲清具体功能带来的价值，此时可嵌套用 FAB 逐条展开；但 FAB 本身不管整体叙事骨架，只负责单个功能的特性-优势-利益翻译。
- **与[SCQA](../scqa/SKILL.md)**：SCQA 是商务汇报/备忘录的问题定义开场，服务的是理性论证场景；SB7 是品牌叙事定位框架，服务的是营销/传播场景，两者应用领域不同，一般不会混淆。

## 记忆钩子

客户才是那个要打怪升级的主角，你只是递给他地图和武器的向导。
