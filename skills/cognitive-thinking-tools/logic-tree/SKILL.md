# 逻辑树 Logic Tree

## 这是什么

**逻辑树**：以树形展示「主问题 / 主假设」如何分解为子问题或子假设，节点之间是支持、穷尽或决策分支关系。常见变体：

| 类型 | 顶层 | 下层 |
|---|---|---|
| **问题/议题树** | 待回答的问题 | 必须先答的子问题 |
| **假设树** | 待检验的主张 | 使其成立所需的子假设 |
| **方案树** | 目标 | 可选路径（后需筛选） |

它把脑子里的一团线变成**可指着讨论的对象**，并自然要求同层尽量 MECE。

## 什么时候用

- "把大问题拆成能分给人做的小问题"
- "假设太多，想看依赖关系"
- 直接说逻辑树 / 议题树 / 问题树 / hypothesis tree

**不要**当主模型：

- 只要分类规则、不要树 → [`mece`](../mece/SKILL.md)
- 带概率与期望值的决策节点 → [`decision-tree`](../../decision-probability/decision-tree/SKILL.md)
- 对外结论先行表达 → [`pyramid-principle`](../pyramid-principle/SKILL.md)
- 总流程不知从何开始 → [`structured-thinking`](../structured-thinking/SKILL.md)

## 怎么用（执行步骤）

1. **写树顶。** 一句问题或一句假设。问题树用问句；假设树用断言。二者勿混在同一顶层。
2. **选分解关系并写边含义。** 「要答父问题必须先答子问题」或「父假设成立仅当子假设皆真 / 任一为真」。判据：父子能否用因为/所以说清？
3. **同层做 MECE。** 调用 MECE：一次一个拆分轴；检查重叠与遗漏。
4. **长到可行动叶子。** 叶子应是可调研、可计算、可实验的问题。仍是口号则继续拆。
5. **标优先级与未知。** 对叶子标影响×不确定，决定先做哪几片；别平均用力。
6. **综合回树顶。** 叶子有答案后，沿边做「所以什么」，更新或否定树顶；必要时改树，不要为保树形扭曲事实。

## 例证

**利润议题树**：「利润为何下降？」→ 收入侧 / 成本侧 → 价、量、固定、变动……揭示公式轴天然适合逻辑树。

**假设树**：「应进入 X 市场」→ 市场规模足够 ∧ 可赢份额 ∧ 能力匹配——任一子假被否，树顶动摇。揭示假设树适合 Go/No-Go。

## 什么时候不适用（边界）

- **强反馈网状系统**：树会切断回路；需系统图补充。
- **过早假设树锁死探索**：早期可用问题树，慎用强断言树。
- **与概率决策树混淆**：要算期望值走 decision-tree。

## 常见误用

- **树很全但无优先级**：叶子海啸 → 步骤 5。
- **父子无逻辑，只是缩进清单**：补「所以/因为」边。
- **把表达金字塔误当分析树**：分析用逻辑树，汇报用金字塔（可同构但目的不同）。

## 相关模型

- **与[MECE](../mece/SKILL.md)**：MECE 是同层纪律；逻辑树是载体。几乎总连用。
- **与[结构化思维](../structured-thinking/SKILL.md)**：结构化思维编排流程；逻辑树是其常用产物。
- **与[决策树](../../decision-probability/decision-tree/SKILL.md)**：决策树含不确定结果与支付；逻辑树分解问题/假设。用户说概率/期望 → 决策树。
- **与[金字塔原理](../pyramid-principle/SKILL.md)**：逻辑树向下问；金字塔向上答。想清楚后常把树顶变塔顶。
- **与[5Why](../five-whys/SKILL.md)**：5Why 是单链；逻辑树可多分支。单故障链可用 5Why；复杂议题用树。

## 记忆钩子

树顶一句人话，叶子都能动手——中间用「所以/因为」粘住，并保持同层不重不漏。
