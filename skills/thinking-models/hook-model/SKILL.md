# HOOK 模型 Hook Model

## 这是什么

Nir Eyal《Hooked》提出的**习惯回路产品设计**框架，四步闭环：

1. **Trigger 触发**：外部（推送、邮件、广告、情境提示）或内部（无聊、恐惧、社交焦虑等情绪线索）。成熟习惯逐渐由内部触发接力。
2. **Action 行动**：用户为求奖励而做的最简行为（打开、滑动、搜索）。行动必须足够容易发生。
3. **Variable Reward 可变奖励**：结果不可完全预测（社交认可、猎物式信息、自我掌握感），提高重复动力；固定奖励易脱敏。
4. **Investment 投入**：用户投入时间、数据、内容、声誉、技能或社交图谱，使产品对*下一次*更有价值，并加载下一轮触发。

它回答的是：**如何让有价值的行为跨会话反复出现**。回路跑通 ≠ 对用户有益——伦理边界必须单独守。

与福格的硬分工：[`fogg-behavior-model`](../fogg-behavior-model/SKILL.md) 用 B=MAP 诊断**这一下**会不会发生；HOOK 在行动能发生的前提下，设计**重复与投入**。可连用：先 MAP 降低 Action 摩擦，再用 Hook 做闭环。

## 什么时候用

- 产品/内容要养成打开—使用—回访习惯；
- 需要拆“触发弱 / 行动难 / 奖励可预测 / 无投入”哪一环断了；
- 用户直接说 HOOK / Hooked / 习惯回路 / 可变奖励。

**不要**当主模型：
- “想跑步却总不去”的单次缺口 → [`fogg-behavior-model`](../fogg-behavior-model/SKILL.md)；
- 待办优先级 → [`eisenhower-matrix`](../../efficiency-execution/eisenhower-matrix/SKILL.md)；
- 战略态势 → [`swot`](../../strategy-competition/swot/SKILL.md)。

## 怎么用（执行步骤）

1. **写清目标习惯行为（一句话、可观察）。** 例如“工作日早上打开 App 完成一道复习题”，禁止“提升粘性”空话。
2. **画四格并填可观察产物。** 触发源是什么？最简 Action 是什么？奖励属哪类（社交/猎物/自我）且何处可变？用户留下什么 Investment？
3. **先保证 Action 过福格门槛。** 若 MAP 过不了行动线，先缩步骤、去摩擦；不要用更吵的 Trigger 硬推。
4. **设计可变，而非纯轰炸。** 明确哪些结果随机/多样；固定打卡积分若完全可预测，要补变化或意义，否则只剩骚扰。
5. **检查投入是否提高*下次*价值且可退出。** 数据/内容/社交图谱应服务用户目标；暗黑锁客、惩罚性流失设计不在本 skill 推荐范围。输出：断环诊断 + 一版伦理内改法。

## 例证

**健身打卡 App**：外部闹钟触发 → 一键记录一组动作（Action）→ 间歇徽章/好友动态（可变）→ 训练历史与计划（投入）。揭示四步如何接力；若 Action 要填三页表，回路在第二步死。

**信息流刷新**：下拉的不可预测内容是猎物式可变奖励；无投入时同质化严重。揭示“可变”可驱动回访，也易滑向空虚刷屏——需内容价值与时长边界。

**（原书卡片）HOOK 回路示意**：四步结构应对齐 Eyal；OCR/励志化版本常缺与福格的区分，且易暗示“让人上瘾=成功”。成功标准应是用户目标达成下的自愿重复，不是操控时长最大化。

## 什么时候不适用（边界）

- **有害成瘾/欺诈/暗黑模式**：不协助设计无法知情退出的强迫回路。
- **单次行为诊断**：未发生过一次，先福格，不先 Hook。
- **强监管/高风险决策**：医疗依从等可用提示与简化，但可变奖励操纵须极谨慎并合规。
- **组织变革**：编制、激励、流程问题不是“加个 Hook”能替代。

## 常见误用

- **把"又打开了"等同于"对用户有价值"**：只盯留存/打开率指标，不检查 Investment 是否真的服务用户目标，还是纯粹被可变奖励钩住却收获寥寥 → 步骤5 要求投入服务用户目标且可退出。
- **为了制造"可变"而堆砌无意义随机内容**：把奖励做成纯噪声式老虎机刷新，用户重复打开却没有真实社交/信息/掌控收获 → 步骤4 要求奖励属于社交、猎物或自我认同某一类，不是随机本身。
- **靠制造"失去连续记录"的损失焦虑驱动重复，而非行为本身有意义**：用红点、连续打卡压力代替真实价值触发 → 相关模型已提示须诚实披露框架，不能单方面用损失规避操纵。
- **Action 本身还过不了福格门槛时，用更密集的 Trigger 硬推**：行动步骤太难、摩擦太大，不去简化却不断加推送轰炸想蛮力启动回路 → 步骤3 要求先保证 Action 过 MAP 门槛再谈闭环。

## 相关模型

- **与[福格行为模型](../fogg-behavior-model/SKILL.md)**：单次 MAP vs 跨会话回路；先发生，再上钩。
- **与[飞轮](../../strategy-competition/flywheel/SKILL.md)**：飞轮是战略增强回路隐喻；HOOK 是产品层触发—奖励—投入的具体四步。
- **与[复利](../../finance-investing-models/compounding/SKILL.md)**：投入累积可类比复利，但须再投入条件成立且非剥削。
- **与[损失规避](../../behavioral-biases/loss-aversion/SKILL.md)**：可用“失去连续记录”作触发，但对用户顾问时应诚实披露框架，不单方面操纵。
