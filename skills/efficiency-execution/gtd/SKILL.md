# GTD Getting Things Done

## 这是什么

**GTD**：通过捕获所有悬而未决事项到外部系统，再澄清（是否可行动、下一步是什么）、组织（清单/项目/等待/将来）、复盘与执行，使大脑从提醒功能中解放。核心产出是**清晰的下一步行动**与定期回顾。

## 什么时候用

- "事情太多，脑子装不下"
- "GTD / 下一步行动 / 收集箱"
- 个人或小团队事务管理系统重建

**不要**当主模型：

- 团队可视化流动与 WIP → [`kanban`](../kanban/SKILL.md)
- 紧急×重要 → [`eisenhower-matrix`](../eisenhower-matrix/SKILL.md)
- 短计时节奏 → [`pomodoro`](../pomodoro/SKILL.md)

## 怎么用（执行步骤）

1. **收集。** 把所有开放循环倒进收集箱（纸/App），脑内不再「靠记得」。判据：想到的是否都有出处。
2. **澄清（逐条处理到空）。** 对每条问：是什么？需要行动吗？两点以上行动 → 项目；下一点必须是**可见的物理/电脑下一步**（「打电话给 X」而非「解决房贷」）。
3. **组织。** 分到：项目清单、下一步清单（可按情境 @电脑/@电话）、等待、日程、将来/也许。
4. **反映（每周回顾）。** 清空收集箱、检查项目是否都有下一步、回顾等待与将来。无回顾则系统腐坏。
5. **执行。** 按情境、时间、精力、优先级选下一步；可用艾森豪威尔辅助优先级。
6. **保持「可信」。** 若开始不信任清单，停下来做回顾而不是再开平行脑内清单。

## 例证

**「整理税务」项目**：下一步写成「下载去年工资单 PDF」——揭示可执行下一步。

**收集箱爆掉**：每周回顾恢复空箱——揭示系统靠回顾维持。

## 什么时候不适用（边界）

- **只需单次待办**：轻量清单即可，不必全套 GTD。
- **高度即时应答岗位**：收集仍有用，但情境清单要适配中断。
- **团队交付流瓶颈**：看看板/关键路径。

## 常见误用

- **下一步写成项目名**：无法执行 → 改写物理动作。
- **只收集不澄清**：坟场收集箱。
- **无每周回顾**：系统死亡。
- **与看板抢团队流**：个人系统用 GTD；团队 WIP 用看板。

## 相关模型

- **与[看板](../kanban/SKILL.md)**：GTD 个人澄清；看板团队流动。
- **与[艾森豪威尔矩阵](../eisenhower-matrix/SKILL.md)**：GTD 执行阶段可叠加紧急重要。
- **与[番茄](../pomodoro/SKILL.md)**：选定下一步后用番茄推进。
- **与[深度工作](../../learning-growth/deep-work/SKILL.md)**：高认知下一步放入深度块。
- **与[PDCA](../pdca/SKILL.md)**：回顾即 Check/Act。

## 记忆钩子

脑子用来想，不用来记；每条落到**下一步动作**并每周回顾。
