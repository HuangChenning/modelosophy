# 八爪鱼图 Octopus Diagram

## 这是什么

**八爪鱼图**：把主题放在中心，向外伸出多条「腕足」，每条腕代表一个分析维度或子题（常约 5–8 条，不必机械凑 8）。它是**广度优先的盘点草图**：先让侧面可见，再决定哪条腕值得加深。

它不是严格分类证明，也不是最终论证结构；完成后通常要把重要腕转入逻辑树、概念图或行动清单。

## 什么时候用

- "先把这个主题可能相关的面铺开"
- "工作坊开场，快速看见死角"
- 直接说八爪鱼图 / 章鱼图 / 放射维度
- 复盘、调研提纲、风险雷达的初稿

**不要**当主模型：

- 要联想层级与记忆结构 → [`mind-map`](../mind-map/SKILL.md)
- 要「A —关系→ B」命题网络 → [`concept-map`](../concept-map/SKILL.md)
- 要主问题严格分解 → [`logic-tree`](../logic-tree/SKILL.md)
- 只要分类纪律 → [`mece`](../mece/SKILL.md)

## 怎么用（执行步骤）

1. **写中心主题（名词或短问题）。** 判据：一条腕说不清整个中心。
2. **先定腕足名（维度），再填内容。** 维度例：客户/成本/风险/合规/技术/时间/对手/依赖。判据：腕与腕尽量不同轴；同义腕合并。
3. **每腕写 2–5 条要点（事实优先）。** 禁止一腕变成小作文；要点可标「已知/假设/未知」。
4. **做覆盖自检。** 问：还有哪个利益相关方/约束完全没腕？补腕或并入。不要求宇宙穷尽，但要相对议题边界无明显盲区。
5. **标加深优先级。** 每腕打：高未知 / 高利害 / 可后置。高未知高利害 → 转 [`logic-tree`](../logic-tree/SKILL.md) 或调研。
6. **回收。** 输出：维度清单 + 下一步（哪三条腕变成分析任务）。八爪图本身不是结论。

## 例证

**新产品上市盘点**：腕=渠道、定价、履约、客服、合规、品牌、数据、依赖供应商——发现「售后备件」无主。揭示：八爪鱼图擅长**暴露缺席维度**。

**会议失败用法**：中心写「成功」，腕全是励志词 → 无效；中心与腕必须可讨论事实与任务。

**（原书卡片）**：若只强调「画八条腿」，忽略维度质量；条数可变，维度独立性优先。

## 什么时候不适用（边界）

- **已进入深拆**：需要多层因果/假设树时，升级工具。
- **强 MECE 交付**：八爪草图可作输入，不能代替 MECE 验收。
- **线性流程说明**：用流程图/时间线，不用放射图硬套。

## 常见误用

- **凑满八条**：空腕充数 → 宁可 5 条实腕。
- **腕足内容重叠**：两腕同一事实 → 合并或改轴。
- **当成最终战略图**：草图当决策 → 必须回收到选型/计划工具。
- **与思维导图不分**：需要自由联想层级时用 mind-map；要固定多维盘点用本模型。

## 相关模型

- **与[思维导图](../mind-map/SKILL.md)**：思维导图层级联想、可深可浅；八爪鱼图强调一次铺开的维度盘点，腕宜短平。
- **与[概念图](../concept-map/SKILL.md)**：概念图要连接词与命题；八爪图通常无命题边。
- **与[逻辑树](../logic-tree/SKILL.md)**：逻辑树回答主问题分解；八爪图回答「有哪些面要看」。重要腕可升级为树。
- **与[MECE](../mece/SKILL.md)**：整理腕足名时用 MECE 检查；八爪图本身不保证穷尽。
- **与[菱形六步法](../diamond-six-steps/SKILL.md)**：常用于步 2 发散探查的可视化。

## 记忆钩子

中心一只「头」，先长出不同方向的腕——看见缺哪条腕，比画得漂亮重要。
