# 在制品限制 WIP Limits

## 这是什么

**WIP 限制**：对「进行中」的工作项数量设硬上限，超限则禁止新开、优先完成或协助卸货。利特尔法则给出恒等式：周期时间 = WIP / 吞吐；它本身不保证降 WIP 就变快——起作用的是减少排队与切换成本、且吞吐不下降。

它是看板方法的**核心政策旋钮**；本 Skill 单抽此旋钮，便于在无完整看板时也能先限并行。

## 什么时候用

- "同时开了十几件事都没完成"
- "WIP / 在制品限制 / 少开坑"
- 个人或团队吞吐不稳、阻塞多

**不要**当主模型：

- 要设计完整列与拉动规则 → [`kanban`](../kanban/SKILL.md)
- 固定冲刺范围与评审 → [`agile-iteration`](../agile-iteration/SKILL.md)
- 依赖网络算工期 → [`critical-path`](../critical-path/SKILL.md)

## 怎么用（执行步骤）

1. **定义「进行中」边界。** 含等待评审吗？写清；模糊则 WIP 无效。
2. **设初始上限。** 个人常 1–3；团队按列容量从紧开始。判据：是否经常撞线。
3. **撞线政策。** 超限：完成、拆小、协助阻塞、或明确升级——禁止默默加塞。
4. **度量周期时间。** 开工→完成；观察降 WIP 后是否缩短。
5. **调参一次改一个。** 上限±1 观察一两周；用数据非感觉。
6. **与批处理区分。** 批处理合并同类；WIP 限制并行件数——可并用。

## 例证

**个人**：Doing≤2，旧坑不完不开新——揭示完成率上升。

**开发**：Review 列 WIP=2，暴露评审瓶颈——揭示限制的诊断力。

## 什么时候不适用（边界）

- **完全串行且天然 WIP=1**：增益有限。
- **外部强制并行（监管多案同时）**：设分池上限，而非假装无限。
- **用 WIP 掩盖优先级混乱**：先艾森豪威尔/吃青蛙选对事。

## 常见误用

- **上限形同虚设**：领导一句话就加塞。
- **WIP 过大等于没有**：失去拉力。
- **只限个人不限等待列**：瓶颈转移到队列。
- **与看板概念对立**：WIP 是看板子集，可先单用。

## 相关模型

- **与[看板](../kanban/SKILL.md)**：看板=可视化+WIP+拉动；本模型聚焦 WIP 旋钮。
- **与[精益思维](../lean-thinking/SKILL.md)**：降在制品减浪费。
- **与[TOC](../../cognitive-thinking-tools/theory-of-constraints/SKILL.md)**：撞线处常是约束。
- **与[批处理](../batching/SKILL.md)**：合并同类 ≠ 提高并行。
- **与[敏捷迭代](../agile-iteration/SKILL.md)**：冲刺也可内嵌 WIP 政策。

## 记忆钩子

少开坑才能快完成——**先设上限，再谈加速**。
