# 站会 Standup / Daily Scrum

## 这是什么

**站会**：团队（或工作流相关成员）以短时间盒（常≤15 分钟）同步：面向冲刺/流目标，各自汇报进展、今日焦点与障碍；障碍会后跟进，不在站会里开设计评审。

它是**节奏化同步仪式**，不是状态汇报给领导的表演，也不是解决问题的工作坊。

## 什么时候用

- "团队不知道彼此卡在哪"
- "站会 / daily standup / 每日同步"
- 敏捷迭代或看板流需要日常对齐

**不要**当主模型：

- 冲刺计划/评审/回顾整套 → [`agile-iteration`](../agile-iteration/SKILL.md)
- 深度排障或决策 → 另开会；可用 [`after-action-review`](../../decision-probability/after-action-review/SKILL.md) 等
- 个人待办澄清 → [`gtd`](../gtd/SKILL.md)

## 怎么用（执行步骤）

1. **固定时间地点/链接与时间盒。** 超时立刻结束并记「会后议题」。
2. **面向共同目标发言。** 每人对着看板/冲刺目标：昨天完成什么、今天计划什么、有何阻碍。
3. **禁止解决方案深潜。** 「阻碍」只点名；兴趣者会后留下（停车坪）。
4. **升级阻塞。** 超 SLA 的阻塞指定负责人与时限。
5. **看板/WIP 可见。** 站会最好站在板前；更新状态勿事后补。
6. **反模式监测。** 变成向经理逐人汇报、或变成小时会 → 立刻纠偏。

## 例证

**开发团队**：15 分钟对板，阻塞拉出会后——揭示同步≠解决问题。

**远程**：摄像头+共享板，严格计时——揭示分布式同样可行。

## 什么时候不适用（边界）

- **完全独立贡献者无共享目标**：同步价值低。
- **危机战时室**：改用更密的作战节奏。
- **两人小组已即时沟通**：可简化或隔日。

## 常见误用

- **向领导汇报会**：失去团队自组织。
- **开成设计评审**：破坏时间盒。
- **无阻塞升级**：每天重复同一卡点。
- **人人读任务列表无目标**：噪声。

## 相关模型

- **与[敏捷迭代](../agile-iteration/SKILL.md)**：站会是迭代内日节奏；迭代管计划-评审-回顾。
- **与[看板](../kanban/SKILL.md)** / **[WIP 限制](../wip-limits/SKILL.md)**：站会对板看流与阻塞。
- **与[持续改进](../continuous-improvement/SKILL.md)**：日障碍是改善输入。
- **与[里程碑规划](../milestone-planning/SKILL.md)**：站会不替代里程碑设定。

## 记忆钩子

站会只做三件事：**进展、今日、阻碍**——解题会后聊。
