# 机制设计 Mechanism Design

## 这是什么

**逆向运用博弈论：先定目标，再设计规则使理性参与人自愿达成。**

Hurwicz / Maskin / Myerson：激励兼容、参与约束、显示原理。拍卖、匹配、公共品付费、平台规则皆属应用。与“分析既定博弈”相反——你写支付与行动集。

## 什么时候用

用户出现以下意图时启用本 Skill：

- "怎么设计规则才激励兼容"
- "机制设计"
- "让人自愿说真话"

**不要**在以下情况套用本模型：

- 既定博弈求纳什 → ../nash-equilibrium/SKILL.md
- 只要具体拍卖出价 → ../auction-theory/SKILL.md
- 稳定匹配程序 → ../matching-theory/SKILL.md

## 怎么用（执行步骤）

1. **写社会目标。** 效率、公平、收入、匹配稳定性——可测。
2. **列参与与激励约束。** 不参与的外部选项；谎报是否更赚。
3. **用显示原理降维。** 先问直接机制下说实话是否可行；再谈实施。
4. **压力测试。** 合谋、预算赤字、信息租金。输出：机制草图 + 约束是否满足。

## 例证

**二价拍卖**：对齐真实报价目标。揭示规则塑造真话。

**公共品 Groves 类机制**：支付规则内化外部性（理想条件）。揭示激励与预算张力。

## 什么时候不适用（边界）

- **信息与合谋**：理论可行现实被钻空。
- **伦理与权力**：不设计掠夺性暗模式坑用户。

## 常见误用

- **只写目标不写约束**：无 IC/IR 不是机制设计。
- **与博弈分析方向颠倒仍混称**：先分清正/逆向。

## 相关模型

- **与[拍卖理论](../auction-theory/SKILL.md)**：机制的一类。
- **与[匹配理论](../matching-theory/SKILL.md)**：非价格配置。
- **与[博弈论](../game-theory/SKILL.md)**：超出入门四块时换专条，勿把全书塞进「博弈论」。
- **与[旅行者困境](../travelers-dilemma/SKILL.md)**：改赔付规则。
- **与[信号博弈](../signaling-games/SKILL.md)**：设计者选规则时走对方。
