# 六顶思考帽 Six Thinking Hats

## 这是什么

六顶思考帽的核心不是“六种性格”，而是**并行思考**：普通争论里，一人乐观、一人批判，双方捍卫立场；并行思考要求全组在同一时间看同一方向，先共同找事实，再共同找价值，再共同找风险。

| 帽子 | 当前只做什么 | 不做什么 |
|---|---|---|
| 蓝 | 定义焦点、安排顺序、总结与下一步 | 夹带自己的内容立场 |
| 白 | 已知事实、缺失信息、来源可信度 | 推测和评价 |
| 红 | 直觉、情绪、顾虑，不要求论证 | 用“我感觉”冒充事实 |
| 黄 | 收益、价值、可行理由 | 无条件乐观 |
| 黑 | 风险、障碍、为何可能不成立 | 攻击人或过早扼杀创意 |
| 绿 | 新方案、替代路径、如何绕过约束 | 边生成边批判 |

## 什么时候用

- 会议中事实、感受与判断反复混线；
- 团队分阵营捍卫“我的方案”；
- 需要先发散再收敛的复杂议题；
- 复盘或方案评审需要完整扫过六种信息。

紧急事故、例行小决定或只有一个人查事实，不值得承担完整流程成本。

## 怎么用

1. **蓝帽开场。** 用一句可回答的问题定义焦点，指定主持人、时间和最终产物。例如“是否在 Q4 上线，会议结束要得到一个决定和三条验证任务”。
2. **选顺序，不机械照表。** 没有唯一固定序列。创意议题可用 `蓝 → 红（初始反应）→ 白 → 绿 → 黄 → 黑 → 红（最终反应）→ 蓝`：先短暂收集未加工感受，绿帽仍放在黑帽之前，避免批判抢跑；风险审计则可增加黑帽时间。顺序要服务于焦点，不是仪式。
3. **全员同时换帽。** 不把小王固定为黑帽、小李固定为绿帽。主持人明确宣布当前帽子，越界内容放入“停车场”，等对应阶段再处理。
4. **每帽产出可检查记录。** 白帽分“已知/未知”；绿帽至少给多个不同机制的方案；黑帽写风险及触发条件；黄帽写价值及成立前提；红帽只记录感受，不要求包装成逻辑。
5. **蓝帽收敛。** 总结共识、分歧、待验证假设、负责人和截止时间。六帽本身不提供选择规则；需要时再用决策树、机会成本或其他工具做最终决策。
6. **复盘流程而非输赢。** 检查是否某帽过度主导、主持人有没有夹带立场、顺序是否导致绿帽被压制。

## 例证

**新产品评审**：白帽先列留存、成本和缺失数据；绿帽提出不同发布方式；黄帽寻找每个方案的价值；黑帽列合规与迁移风险；红帽让团队说出“虽然数据好，但我不放心”的直觉；蓝帽把未解决顾虑变成验证任务。它揭示的是感受可以合法出现，但不能伪装成事实。

**从辩论到合作**：两部门围绕同一方案对抗时，让双方同时戴黄帽寻找价值，再同时戴黑帽找漏洞。观点不再属于某个人，而属于当前帽子，降低“承认对方正确等于我输了”的身份成本。

**（原书卡片）六帽功能图**：卡片对颜色定义大体准确，也提到蓝帽过程控制；但若只让不同成员各戴一顶帽，会退化成角色分工，失去“全员同时看同一方向”的并行思考内核。

## 什么时候不适用

- **证据有限**：实证支持主要是案例与培训报告，不应声称六帽必然提高决策质量。
- **无熟练蓝帽**：流程容易变成道具剧场或无序轮流发言。
- **帽子人格化**：“你就是黑帽”会污名化成员，正好恢复本方法要消除的立场对抗。
- **黑帽过早/过强**：会掐死绿帽；顺序本身是干预变量。
- **没有收敛规则**：六帽能丰富信息，不能自动计算答案。

## 常见误用

- **把帽子固定分给不同人**：让擅长挑刺的人专职戴黑帽、乐观的人专职戴黄帽，变成角色分工而不是全员同一时刻看同一方向 → 违反并行思考的核心机制，等于走回了立场对抗。
- **红帽发言被要求讲道理**：有人说出直觉顾虑，主持人或其他人追问"你的依据是什么"，逼红帽伪装成分析 → 红帽本就不要求论证，硬要论证只会让顾虑不敢再被说出来。
- **黑帽抢跑压制绿帽**：讨论还在生成方案阶段，就有人开始列风险和"这做不到"，创意还没说完就被否决 → 顺序本身是干预变量，黑帽应晚于绿帽，或明确分配单独时段。
- **没有蓝帽也硬转六轮**：没人定焦点、控时间、做收敛，六种发言方式混着来，最后没有决定也没有下一步 → 缺蓝帽主持时，流程会退化成道具剧场。

## 相关模型

- **与[苏格拉底式质疑](../../thinking-models/socratic-questioning/SKILL.md)**：六帽组织群体并行探索；苏格拉底式质疑沿一条主张追问到矛盾显现。
- **与[确认性偏差](../../behavioral-biases/confirmation-bias/SKILL.md)**：黑帽与白帽可制造结构性反证，但若主持人预先偏向结论，六帽仍会被确认性偏差污染。
- **与[决策树](../../decision-probability/decision-tree/SKILL.md)**：六帽负责搜集完整输入；决策树负责把不确定选项、概率和效用折叠成选择。
