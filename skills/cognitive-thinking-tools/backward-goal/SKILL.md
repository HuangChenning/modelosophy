# 反向目标 Backward Goal

## 这是什么

**反向目标**：先定义「成功完成时长什么样」（可观察终态），再问「要出现这一终态，上一步必须已具备什么」，一路倒推到当下可执行动作与依赖。它把目标从愿望句变成**带验收标准的状态链**。

与「从今天能做什么往前凑」相反：正向堆砌容易忙碌但到不了终点；反向倒推暴露缺失的前置条件与虚假里程碑。

## 什么时候用

- "目标很大，不知道从哪拆"
- "以终为始 / 先定义成功再排期"
- 直接说反向目标 / backward planning / 从终点倒推
- OKR、项目计划、个人目标需要可验收终态

**不要**当主模型：

- "怎样保证搞砸、列回避项" → [`inversion`](../inversion/SKILL.md)
- 多方案带概率比较 → [`decision-tree`](../../decision-probability/decision-tree/SKILL.md) / [`decision-matrix`](../decision-matrix/SKILL.md)
- 终态未定、还在探索问题 → [`scqa`](../scqa/SKILL.md) / [`structured-thinking`](../structured-thinking/SKILL.md)

## 怎么用（执行步骤）

1. **写终态验收句（Definition of Done）。** 必须含可观察结果 + 时间窗（「Q3 末付费留存 ≥ X，且工单类 Y 归零」）。判据：陌生人能否判定达成/未达成？禁止「变好/领先」。
2. **倒推关键前置状态。** 问：「若终态已成立，紧前必须为真的是什么？」每层写状态，不写励志。画成链：`终态 ← 状态n ← … ← 今日`。
3. **区分必要与可选。** 对每个前置标：必要（缺则终态不可能）/ 加速器（有更好）。判据：拿掉必要项后终态是否仍可能？
4. **暴露依赖与风险点。** 标外部依赖（审批、供应商、季节）；对高风险必要项，可连用 inversion 做失败预演，但不替代终态链。
5. **落到下一步动作。** 只取链上距今最近、且你可控的 1–3 个动作，各带完成判据。若最近动作仍不可控，终态或范围要改，而不是假装计划。
6. **正向复核一次。** 从今日动作顺推是否合理到达终态；发现跳步（中间状态被跳过）则补层。禁止用「努力」填洞。

## 例证

**产品发布**：终态「某日对公有云开放且错误率 < 阈值」← 金丝雀完成 ← 压力测试通过 ← 特性冻结…… 倒推发现「文档与权限模型」是必要前置却从未排期。揭示：反向目标专抓**假进度**。

**个人学习**：「三个月能独立完成某类项目」← 作品集两件 ← 每周反馈循环…… 比「多看视频」正向堆砌更可验收。

**（原书卡片）**：若只写「从目标反着想」而无验收句，易与 inversion 混淆；本 Skill 以 DoD + 状态链为准。

## 什么时候不适用（边界）

- **终态不可知的探索**：研究早期先问题定义，不硬造假终态。
- **对抗性环境终态被对手改写**：需动态重钉终态，单次倒推不够。
- **伦理上不该优化的终点**：倒推会让不义目标更「可执行」——先审目标合法性。

## 常见误用

- **与逆向思维混淆**：列失败原因当反向目标 → 失败预演走 inversion；成功路径走本模型。
- **终态仍是口号**：无验收 → 先改写 DoD。
- **倒推成愿望清单**：层与层无「必要」关系 → 删掉励志节点。
- **只倒推不复核**：顺推发现不可达却不改终态 → 缩小范围或加资源。

## 相关模型

- **与[逆向思维](../inversion/SKILL.md)**：**硬区分。** 成功终态倒推路径 → 本模型；失败模式→回避清单 → inversion。高利害项目可先本模型建链，再 inversion 压测链上弱点。
- **与[逻辑树](../logic-tree/SKILL.md)**：逻辑树分解问题/假设；反向目标分解时间与状态依赖。
- **与[结构化思维](../structured-thinking/SKILL.md)**：总流程里「综合/计划」阶段常用本模型。
- **与[TOC 约束理论](../theory-of-constraints/SKILL.md)**：倒推时若吞吐被瓶颈卡死，先处理约束再堆里程碑。
- **与[优劣势清单](../pros-cons-list/SKILL.md)**：终态选项未定时可先利弊粗筛，再对选定终态倒推。

## 记忆钩子

先写「完成时长什么样」，再问「少了哪一块就到不了」——从终点往回铺路。
