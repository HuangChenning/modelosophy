# 甘特图 Gantt Chart

## 这是什么

**甘特图**：用时间轴上的横条表示任务起止，可选地标出依赖、里程碑与进度百分比。它擅长**沟通计划与实际的时间占用**，本身不自动给出「哪条链决定工期」——那是关键路径分析。

甘特是**可视化排程语言**；关键路径是**网络算法结论**；里程碑是**阶段门**。

## 什么时候用

- "要给干系人看任务时间条"
- "甘特图 / Gantt / 排程条形图"
- 多任务并行需要看见重叠与空档

**不要**当主模型：

- 计算决定工期的最长链 → [`critical-path`](../critical-path/SKILL.md)
- 只定义阶段验收门 → [`milestone-planning`](../milestone-planning/SKILL.md)
- 流动与 WIP → [`kanban`](../kanban/SKILL.md)

## 怎么用（执行步骤）

1. **列出工作包到可估时粒度。** 过大先拆；过碎则噪声。
2. **估工期并标依赖。** FS/SS 等关系写清；无依赖不要假连。
3. **画条并放里程碑。** 条=工作；菱形/标记=门。
4. **对照关键路径。** 用网络法标出关键任务，甘特上高亮——勿假装所有条同等关键。
5. **更新实际进度。** 基线 vs 实际；延误时调范围或资源，而非只涂色。
6. **防止假精确。** 不确定段用区间/缓冲；承认甘特会被计划谬误击穿。

## 例证

**建筑分包**：条形图协调进场顺序——揭示并行与交接。

**软件发版**：甘特作沟通，关键路径管能否按期——揭示工具分工。

## 什么时候不适用（边界）

- **高变化看板流**：甘特易过时，改看板+里程碑。
- **探索性工作无稳定任务集**：先学习再排。
- **只为「看起来专业」而画**：无依赖与更新=装饰。

## 常见误用

- **甘特=项目管理全部**：缺风险、质量、人。
- **用甘特代替关键路径**：条长≠关键。
- **从不重基线**：变成谎言图。
- **任务切到小时级**：维护成本爆炸。

## 相关模型

- **与[关键路径](../critical-path/SKILL.md)**：**硬分流。** 关键路径算最长链；甘特展示条与时间。常连用：路径结论画在甘特上。
- **与[里程碑规划](../milestone-planning/SKILL.md)**：先门后条，或条中嵌门。
- **与[计划谬误](../../decision-probability/planning-fallacy/SKILL.md)**：估条时长加参考类。
- **与[看板](../kanban/SKILL.md)**：流式交付慎用重甘特。

## 记忆钩子

甘特是**时间条说明书**；谁决定能不能按期，看关键路径。
