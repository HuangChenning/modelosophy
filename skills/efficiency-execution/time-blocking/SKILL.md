# 时间块 Time Blocking

## 这是什么

**时间块**：预先把日历切成用途明确的连续时段（写稿、会议、行政、缓冲），任务进入块而非开放待办。目标是减少切换成本、让意图可见、为高认知工作留硬边界。

它是**日历层排程工具**，不是优先级矩阵（艾森豪威尔），也不是短铃节奏（番茄）。深度无扰块的设计意图见学习类深度工作；本模型负责「块如何落进日历」。

## 什么时候用

用户出现以下意图时启用本 Skill：

- "日程被会议打成碎片，想把重要事写进日历"
- "时间块 / time blocking / 日历排程"
- 需要可见缓冲与主题日（theme days）

**不要**在以下情况套用本模型：

- 只问紧急重要分流 → [`eisenhower-matrix`](../eisenhower-matrix/SKILL.md)
- 只要 25 分钟启动节奏 → [`pomodoro`](../pomodoro/SKILL.md)
- 设计长无扰高认知协议（主条）→ [`deep-work`](../../learning-growth/deep-work/SKILL.md)

## 怎么用（执行步骤）

1. **先定本周不可协商块。** 睡眠、已定会议、通勤先占位；判据：日历上空白是否真实可用。
2. **为高认知任务分配命名块。** 块标题写产出物（「完成方案 v1」），不写模糊「工作」；单块建议 60–120 分钟。
3. **插入缓冲与切换缝。** 会议间留 10–15 分钟；行政合并到固定行政块。判据：连续会议是否仍留呼吸缝。
4. **批量同类任务进同主题块。** 邮件/审批进批处理块；与 [`batching`](../batching/SKILL.md) 连用。
5. **日终对照实际。** 记下被打断的块；次日调整块长度或防护规则，而非只怪意志力。
6. **块被打破时的规则。** 紧急插入须标明牺牲了哪块；事后补回或缩范围，禁止默默堆叠。

## 例证

**作家日历**：上午写作块、下午通信块——揭示「意图进日历」降低开放清单焦虑。

**经理主题日**：周一规划、周三一对一、周五深度——揭示主题日减少上下文切换。

## 什么时候不适用（边界）

- **真实随时响应岗**（一线值班）：硬块可能有害，改用值班窗 + 短块。
- **工期由依赖网络决定**：先 [`critical-path`](../critical-path/SKILL.md) / [`gantt-chart`](../gantt-chart/SKILL.md)。
- **精力与时间错配**：先 [`energy-management`](../energy-management/SKILL.md)。

## 常见误用

- **把待办整表贴进日历无缓冲**：假精确 → 预留 20–30% 弹性。
- **块内多任务切换**：失去块义 → 一块一事。
- **与深度工作等同**：深度工作管无扰协议；时间块管落盘。
- **会议填满才叫满日历**：会议不是唯一合法块。

## 相关模型

- **与[深度工作](../../learning-growth/deep-work/SKILL.md)**：**硬分流。** 深度工作=无扰高认知协议（学习类主条）；时间块=把意图写入日历。可连用：先定深度块再排日历。
- **与[番茄工作法](../pomodoro/SKILL.md)**：番茄=短盒节奏；时间块=更长主题时段。
- **与[艾森豪威尔矩阵](../eisenhower-matrix/SKILL.md)**：先选重要，再块化。
- **与[批处理](../batching/SKILL.md)**：同类事务进同一行政块。
- **与[帕累托法则](../../systems-classic-effects/pareto-principle/SKILL.md)**：80/20 时间用法只互链——先找关键少数，再给它们块。

## 记忆钩子

意图不进日历，就只是愿望——**先切块，再开工**。
