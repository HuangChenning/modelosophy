# TRIZ 发明原理 TRIZ (Theory of Inventive Problem Solving)

## 这是什么

**TRIZ**（俄语 Теория решения изобретательских задач 的拉丁转写）：Altshuller 等通过大量专利研究总结的**发明问题**方法论。核心洞察：很多「创新难题」是**矛盾**——改善某参数会恶化另一参数（技术矛盾），或同一对象需要互斥状态（物理矛盾）；突破往往来自**消除矛盾**，而非永久折中。

本 Skill 落地为可执行子集（完整 TRIZ 含物质-场、标准解、ARIZ 等，此处不假装一次教完）：

1. 陈述**理想最终结果（IFR）**  
2. 识别并分类矛盾（技术 vs 物理）  
3. 对物理矛盾尝试**分离**（时间/空间/条件/层级）  
4. 对技术矛盾用**发明原理启发**（40 原理作检查清单，非魔法公式）  
5. 把候选解变回可验证方案  

## 什么时候用

- "产品又要轻又要硬 / 又要快又要稳"
- "设计陷入 A 与 B 的权衡拉锯"
- 直接提 TRIZ / 发明原理 / 技术矛盾 / 物理矛盾
- 专利/工程创新需要跳出常规折中

**不要**当主模型：

- 故障为何发生 → [`five-whys`](../five-whys/SKILL.md)
- 产线/流程吞吐瓶颈 → [`theory-of-constraints`](../theory-of-constraints/SKILL.md)
- 挑战行业惯例、从硬约束重算 → [`first-principles`](../first-principles/SKILL.md)（可与 TRIZ 连用：第一性定约束，TRIZ 解矛盾）
- 纯沟通结构/汇报 → [`scqa`](../scqa/SKILL.md) / [`pyramid-principle`](../pyramid-principle/SKILL.md)
- 会议分角色发散 → [`six-thinking-hats`](../six-thinking-hats/SKILL.md) 或 [`lateral-thinking`](../lateral-thinking/SKILL.md)

## 怎么用（执行步骤）

1. **写问题与 IFR。** 「在不增加有害因素的前提下，系统自己完成所需功能」——理想最终结果作方向标，不是幻想规格。判据：IFR 是否消除了「必须靠人盯 / 必须永久牺牲 B」？
2. **抽取矛盾句。** 技术矛盾模板：「改善参数 P1（如强度）导致参数 P2 恶化（如重量）」。物理矛盾模板：「对象在条件 C 下必须有属性 A，在条件 D 下必须有非 A」。写不出矛盾句 → 先澄清需求，勿硬套 40 原理。
3. **优先尝试分离（物理矛盾）。**  
   - 时间分离：不同时刻不同状态  
   - 空间分离：不同部位不同状态  
   - 条件分离：不同条件下切换  
   - 系统层级分离：整体与部分不同属性  
   判据：是否还需要「永久折中」？若否，记录候选解。
4. **技术矛盾：用发明原理作启发清单。** 从相关原理抽样（如分割、预先作用、反向作用、动态化、复合材料、中介物等），每条只问：「若强制用这条，方案长什么样？」产出 3–7 个粗糙概念，禁止假装查过「矛盾矩阵官方答案」却给不出机制。
5. **落地与验证。** 每个概念写：改哪个部件/流程、预期消除哪一臂矛盾、如何用原型或计算证伪。选 1–2 个进入试验；失败则换原理或重写矛盾。
6. **资源扫描（短）。** 系统内已有的能量、物质、时间、信息能否被「自服务」利用？避免一上来外加复杂装置。

## 例证

**自行车头盔（教学向）**：要「开口透气」又要「闭合防护」——空间/条件分离启发：开孔结构 + 能量吸收材料分区，而非无限加厚。揭示：矛盾被**结构化**，不是口号「兼顾」。

**软件产品「可配置 vs 简单」**：物理矛盾「同一界面既要专家全能又要新手极简」→ 时间/条件分离：模式切换、渐进披露、默认简单+可选深度。揭示：TRIZ 不限于机械，但必须能落到**可切换状态**。

**失败用法**：把 40 原理当海报随机贴到商业计划 → 无矛盾定义则 TRIZ 空洞。揭示：步骤 2 是门禁。

## 什么时候不适用（边界）

- **无工程/功能矛盾，只是利益分配**：谈判与治理问题，不要伪 TRIZ。
- **科学未知主导**：基本机理未明，先研究再发明；TRIZ 不能代替实验科学。
- **把矩阵当自动售货机**：当代开源/商业矛盾矩阵质量参差；原理是启发，不是定理证明。
- **监管/伦理硬约束**：某些「矛盾」实为不可逾越的合规边界，应标硬约束而非强行发明绕过。

## 常见误用

- **未写矛盾就翻 40 原理**：像抽卡 → 先完成步骤 2。
- **折中冒充解决**：P1、P2 各让一半 → 这是权衡，不是 TRIZ 成功；除非暂时可接受并标明。
- **与水平思考混淆**：水平思考泛化跳框；TRIZ 锚定矛盾与原理清单。要跳框发散可先水平思考，收敛解矛盾用 TRIZ。
- **与第一性原理混淆**：第一性原理拆惯例重建；TRIZ 在已识别矛盾上检索解法模式。常连用。

## 相关模型

- **与[第一性原理](../first-principles/SKILL.md)**：第一性定硬约束与可丢惯例；TRIZ 在约束内消除矛盾。用户说「行业报价是不是物理」走第一性；「又要又不要的设计矛盾」走 TRIZ。
- **与[TOC](../theory-of-constraints/SKILL.md)**：TOC 管系统瓶颈；TRIZ 管发明矛盾。吞吐问题走 TOC；产品/工艺矛盾走 TRIZ。
- **与[水平思考](../lateral-thinking/SKILL.md)**：水平思考刺激跳框想法；TRIZ 提供矛盾驱动的结构化启发。可先水平发散，再用 TRIZ 检验是否真消除矛盾。
- **与[5Why](../five-whys/SKILL.md)**：5Why 找失效根因；根因若呈现为设计矛盾，可交接 TRIZ 生成解。
- **与[逆向思维](../inversion/SKILL.md)**：逆向列失败模式；TRIZ 针对矛盾发明。可连用做风险预演。

## 记忆钩子

别永远折中：先写出「又要又不要」，再分离或换原理——矛盾是入口，不是死局。
