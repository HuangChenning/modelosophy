# 核心能力 Core Competence

## 这是什么

**核心能力**：组织内**协调多种生产技能与技术流**的学习型能力集合——应通过三测：**提供进入多种市场的潜力、对终端产品的顾客可感知利益有显著贡献、竞争对手难以模仿**。它强调公司是能力的组合，而非仅是业务组合。

C.K. Prahalad 与 Gary Hamel（1990）提出，批评过度财务化的 SBU 切割导致能力碎片化。与 **RBV/VRIO** 近亲：RBV 是理论透镜，VRIO 是资源条目审计；核心能力更强调**跨业务共享的能力平台**与产品树根干。

## 什么时候用

- "我们的核心竞争力是什么 / 能否延伸"
- "业务很多，底层能力是否共用"
- 决定自制、协作或退出某能力域

**不要**当主模型：

- 逐条资源打 V/R/I/O → [`vrio`](../vrio/SKILL.md)
- 资源基础观总论与假设 → [`resource-based-view`](../resource-based-view/SKILL.md)
- 投资人视角壁垒类型 → [`economic-moat`](../economic-moat/SKILL.md)
- 心智定位句 → [`positioning`](../positioning/SKILL.md)

## 怎么用（执行步骤）

1. **列出候选「能力」而非产品名。** 例：「精密机电集成」「冷链履约调度」。判据：能描述如何做事，而非卖什么 SKU。
2. **过三测。** (a) 多市场入口 (b) 顾客可感知贡献 (c) 难模仿（含隐默知识与协调）。判据：任一明显失败则降级为普通能力。
3. **画能力—产品树。** 根=核心能力，干=核心产品/平台，叶=终端产品。判据：能指出哪些 SBU 在「租用」同一根能力。
4. **查组织是否在削弱根。** SBU 墙、重复外包、能力预算被砍。判据：标出碎片化证据。
5. **决定投资、保护、共享机制。** 核心能力要有跨 SBU 的主人与标准。判据：有 owner；否则只是口号。
6. **输出能力议程。** 加强/退出/外取；与安索夫延伸选项对齐。

## 例证

**能力根支撑多叶产品**：同一底层能力进入多品类，缩短新品周期——揭示核心能力的「多市场入口」。

**SBU 切割砍断共享**：各事业部重复造轮子并外包关键工艺——揭示财务墙对能力的伤害（Hamel/Prahalad 批评点）。

**与 VRIO 连用**：先用核心能力找到「能力假说」，再用 VRIO 检验是否真稀缺难模仿且有组织支持。

## 什么时候不适用（边界）

- **单产品初创、无跨市场议题**：用更轻的能力/MVP 学习即可。
- **能力声称无法操作化**：改回具体流程与人才清单。
- **外部产业突变使能力过时**：先五力/颠覆视角，再谈延伸。

## 常见误用

- **把产品当核心能力**：「我们的核心能力是手机」→ 改写为能力。
- **与定位互换**：定位是心智；能力是组织擅长。
- **清单膨胀**：二十项「核心」=没有核心 → 压到极少根能力。
- **忽略组织机制**：口头重视、预算与编制不支持。

## 相关模型

- **与[资源基础观](../resource-based-view/SKILL.md)**：RBV 提供「租从来自异质资源」总论；核心能力是其中强调共享能力平台的分支。
- **与[VRIO](../vrio/SKILL.md)**：VRIO 审计条目；核心能力强调跨业务根干。
- **与[安索夫矩阵](../ansoff-matrix/SKILL.md)**：延伸前先问能力是否可迁移。
- **与[护城河](../economic-moat/SKILL.md)**：护城河分类壁垒；核心能力解释内部能力引擎。

## 记忆钩子

核心能力 = **树根**：过「多市场 / 顾客利益 / 难模仿」三测，并有跨业务共享机制。
