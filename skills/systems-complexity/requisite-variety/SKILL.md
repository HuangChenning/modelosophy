# 必要多样性 Requisite Variety

## 这是什么

**必要多样性（Ashby）**：只有多样性才能吸收多样性——**调节器/控制者必须具备不少于环境扰动的响应品种**，才能稳定住关键变量。扰动花样多于你的对策菜单 → 必然有你管不住的局面。

操作翻译：先盘点「世界能怎么搞你」，再盘点「你能怎么应」，补齐缺口或**缩小需控变量**（降目标多样性）。

## 什么时候用

- "规则太粗，总被钻空子 / 意外打脸"
- "必要多样性 / Ashby / 管控手段是不是太少"
- 风控、客服话术库、安全响应、平台治理、个人应急计划

**不要**当主模型：
- 只要负反馈设定点 → [`homeostasis`](../homeostasis/SKILL.md)
- 只要熵增叙事 → [`entropy-increase`](../../systems-classic-effects/entropy-increase/SKILL.md)
- 只要加网络冗余边 → [`network-topology`](../network-topology/SKILL.md)

## 怎么用（执行步骤）

1. **界定要稳定的结果。** 什么变量必须守住？（安全、履约、信任）。
2. **枚举扰动品种。** 环境/对手/故障能以哪些 qualitatively 不同方式来？用 MECE 或场景表。判据：列表≥实际常见类。
3. **枚举响应品种。** 你现有对策、权限、工具、剧本。判据：可执行菜单。
4. **做匹配缺口。** 哪类扰动无对应响应？标红。
5. **补齐或收缩。** 补响应（训练、工具、授权、模块）；或减少需控范围/暴露面（收缩产品表面、限域）。判据：缺口下降。
6. **警惕假多样性。** 十份复印件流程 ≠ 十种响应；多样性指**可区分的有效动作**。

## 例证

**免疫系统**：多样受体应对多样病原。揭示：品种匹配。

**只靠「加班」应对所有项目风险**：响应品种=1，扰动很多 → 必然失败。揭示：要补风险菜单。

**（原书卡片）**：避免「以复杂制复杂」空话；落到扰动×响应矩阵。

## 什么时候不适用（边界）

- **扰动不可观测**：先传感（连稳态）。
- **法律/伦理禁止某些响应**：多样性受约束，需缩暴露。
- **单次简单问题**：不必抬出 Ashby。

## 常见误用

- **堆官僚当多样性**：文件多≠响应多。
- **无限扩权**：「我要更多工具」须对应扰动清单。
- **与熵增混用**：熵增是趋势；必要多样性是控制匹配律。

## 相关模型

- **与[内稳态](../homeostasis/SKILL.md)**：稳态回路的效应器菜单受必要多样性约束。
- **与[熵增](../../systems-classic-effects/entropy-increase/SKILL.md)**：无足够调控多样性时更易失序。
- **与[红队](../../decision-probability/red-team/SKILL.md)**：主动扩展「扰动品种」清单。
- **与[情景规划](../../decision-probability/scenario-planning/SKILL.md)**：情景用来枚举扰动空间。
