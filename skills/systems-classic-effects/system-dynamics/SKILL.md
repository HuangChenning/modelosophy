# 系统动力学 System Dynamics

## 这是什么

**系统动力学**（Jay Forrester 起源）：用**存量（积量）**、**流量（速率）**、**反馈**与**延迟**为语言，解释并仿真系统如何产生增长、目标追寻、过冲、振荡、崩溃等**随时间的行为模式**。

它比口头“系统思维”更强调可计算结构；比纯回路图更强调守恒与单位一致。Meadows 等将其带入政策与可持续讨论。

## 什么时候用

- "为什么政策短期好长期糟"
- "库存/人员/口碑呈现振荡"
- "想做 what-if 结构实验"

**不要**当主模型：
- 只判别回路极性 → [`feedback-loops`](../feedback-loops/SKILL.md)
- 宽泛改事件叙述为结构 → [`systems-thinking`](../systems-thinking/SKILL.md)
- 初值混沌预报 → [`butterfly-effect`](../butterfly-effect/SKILL.md)

## 怎么用（执行步骤）

1. **定义参考模式。** 画出关键变量随时间的历史曲线（升、S 曲线、振荡…）——模型要对准行为，不是对准漂亮图。
2. **列存量与流量。** 存量单位；流量是存量/时间；检查守恒（流入−流出=存量变化）。
3. **连反馈与延迟。** 信息延迟、物质延迟分开；标在图上。
4. **写最小方程或定性速率法则。** 即使不仿真，也要写“流量如何依赖存量/目标”。
5. **做政策实验。** 只改一处结构（目标、延迟、产能），预测参考模式如何变；有条件则跑简单仿真验证。

## 例证

**库存-劳动力模型**：招聘延迟导致员工与订单振荡。揭示**延迟型波动**。

**城市/产业动力学（Forrester）**：住房与业务迁移的长期效应。揭示政策反直觉。

**增长极限类讨论**：资源存量与污染流量框架（争议与简化需注明）。揭示全球模型传统。

## 什么时候不适用（边界）

- **数据与结构双缺**：先做系统思维定性，勿假装精确仿真。
- **高频交易微观结构**：工具栈不同。
- **纯优化排程**：OR 方法可能更直接。

## 常见误用

- **模型炫技**：节点爆炸失去解释力。
- **把仿真当预言**：情景工具不是水晶球。
- **与系统思维互相取代**：一个是学科方法，一个是实践总论——可分层用。

## 相关模型

- **与[系统思维](../systems-thinking/SKILL.md)**：先思维后动力学，或反过来用动力学深化。
- **与[反馈回路](../feedback-loops/SKILL.md)**：回路是动力学的积木。
- **与[杠杆](../../systems-complexity/leverage/SKILL.md)**：Meadows 杠杆点常基于动力学直觉（互链不迁入）。

## 记忆钩子

存量是浴缸，流量是水龙头——对准时间曲线再改结构。
