# 奥卡姆剃刀 Occam's Razor

## 这是什么

14世纪逻辑学家 William of Ockham 提出的"如无必要，勿增实体"（lex parsimoniae）：当同一个观测事实可以被多个理论同时解释时，优先选择所需假设更少的那个。

**关键在于"为什么"**：不是因为"简单的一定对"，而是因为**更简单的理论假设更少、更容易被证伪，因此更经得起检验**。这是科学方法论的核心启发式，现代统计学中模型选择准则（AIC/BIC 对模型复杂度的惩罚项）就是它的量化版本。

## 什么时候用

用户手上有**多个都能自洽解释同一现象的假设**，需要决定先验证哪个时：

- 故障排查："服务挂了，可能是网络、可能是数据库、可能是新上线的代码……"
- 归因分析："这个月销量下滑，是季节因素、竞品、还是我们改了定价？"
- 用户直接问"最可能的原因是什么""是不是我想复杂了"。

## 怎么用（执行步骤）

1. **列出所有能解释该现象的候选理论**——不要只列出用户已经想到的那个。
2. **比较各理论的假设负担**——注意"数假设个数"并没有客观标准（同一个解释拆开写就变多条），所以不要真的去数数字。可操作的判据是：**这个解释里，有哪些环节是为了让它自圆其说而额外追加的？**（即特设假设 ad hoc hypothesis——一旦去掉，解释就不成立，但它本身又没有独立证据支持。）需要这类补丁越多的理论，优先级越低。
3. **检查基础概率（base rate）**——这一步经常被跳过，但很关键。"闻蹄声想到马而非斑马"只在你不在斑马常见的地区时成立。问清楚：在用户所处的**具体情境**下，哪个原因本来就更常见？
4. **按"假设最少 + 可证伪性最高"排序，作为排查顺序**——注意输出的是**验证优先级**，不是最终结论。奥卡姆剃刀告诉你"先查哪个"，不告诉你"答案就是哪个"。
5. **保留复杂解释的可能性**——如果简单解释被证据排除了，要果断转向更复杂的解释，而不是继续为简单解释打补丁（那本身就是在增加特设假设）。

## 例证

**日心说取代地心说（科学史最经典应用）**：托勒密地心说为了解释行星逆行现象，需要不断追加"本轮"（epicycle）这类特设假设，模型越修补越臃肿；哥白尼日心说用更少的假设自洽解释了同样的观测数据。注意这个案例的完整含义——日心说早期在**预测精度上并不优于**地心说，它胜出靠的是结构上的简洁性，这说明奥卡姆剃刀选的是"更值得优先研究的方向"，而不是"立刻就更准的答案"。

**统计学中的模型选择准则（AIC / BIC）**：现代统计学把奥卡姆剃刀量化成了公式——AIC/BIC 在评估模型时会对参数数量施加惩罚项，防止用过度复杂的模型去拟合数据。这解决的正是机器学习中的过拟合问题：参数越多的模型总能把训练数据拟合得更好，但泛化能力更差。**这是"简单假设更可靠"最严格的数学表达。**

**软件故障排查中的实践**：线上服务异常时，经验丰富的工程师会先检查最近一次变更（部署、配置修改），而不是先假设是底层框架的隐藏 bug。原因就是假设数量——"新代码引入了问题"只需要一个假设，"用了多年的框架突然出现罕见 bug"需要额外解释"为什么偏偏现在触发"。

**（原书卡片）诊断学谚语**："闻蹄声，应该想到马，而非斑马"。这句话在医学院被广泛引用，但它同时也是理解本模型边界的最好入口——原话在斑马常见的地区就不成立，这正说明基础概率（base rate）是应用前提。

## 什么时候不适用（边界）

**这是全书 100 个模型中少数原书自己就点明了边界的（原书"特别注意"里写明它是"双刃剑，用不好会割到自己"），这里在此基础上进一步补全：**

- **爱因斯坦的补充**："凡事应该尽可能简单，但不能过于简单。" 对本质上复杂、多因的现象（罕见病、生态系统、组织行为、复杂系统故障），强行套用最简单解释会导致漏诊、漏判，而这类领域里误判的代价往往很高。
- **忽略基础概率会系统性误判**：诊断学谚语本身带有隐含前提——"想到马而非斑马"只在斑马罕见的地区成立。脱离具体情境的基础概率谈"最简单解释"，会得出系统性错误的结论。
- **"简单"本身是主观的**：一个理论"假设更少"有时不容易客观判定，尤其在跨学科比较时。当两个理论的复杂度难分伯仲，奥卡姆剃刀给不出答案，应该转向"哪个更容易被现有证据证伪"来决策。
- **它是启发式，不是证明**：奥卡姆剃刀从来不能证明一个理论为真，只能给出优先级。不要用它作为"所以答案就是X"的结论依据。

## 常见误用

- **把"更简单"当"更正确"**：找到假设最少的解释后直接宣布这就是答案，不再验证 → 违反第 4 步，奥卡姆剃刀只给出验证优先级，不给最终结论。
- **真的去数假设条数**：争论"我的理论只有两个假设，你的有四个"，把拆解粒度当客观标尺 → 假设个数没有客观标准，应该识别的是特设假设（为自圆其说临时追加、且无独立证据的补丁），而不是数数字。
- **脱离情境套用 base rate 谚语**：不管自己是否身处"斑马常见"的场景，机械引用"闻蹄声想到马"当挡箭牌 → base rate 必须针对当前具体情境重新核实，不是可以到处套用的通用格言。
- **简单解释被推翻后继续打补丁**：证据已经排除了最简单的解释，却不断追加特设条件维持它成立 → 这本身就是在增加特设假设，违背模型初衷，应转向下一个更复杂的候选解释。

## 相关模型

与[反脆弱](../../learning-growth/antifragility/SKILL.md)互补：本模型处理"多个解释选哪个"（认识论问题），反脆弱处理"不确定环境下怎么配置资源"（策略问题）。若用户的问题是"该怎么应对不确定性"而非"哪个解释更可能对"，应走反脆弱而非本模型。

与[确认性偏差](../../behavioral-biases/confirmation-bias/SKILL.md)：本模型假定候选解释已经摆上台面，只排验证顺序；确认性偏差管的是解释和证据会不会被先验信念滤掉。用户说"先查哪个"走本模型；用户说"我是不是只看见支持我的"走确认性偏差。常连用：先补上被滤掉的反面解释，再按奥卡姆剃刀排序。

与[易得性启发](../../behavioral-biases/availability-heuristic/SKILL.md)：本模型比较多个解释的假设负担；易得性启发检查某个解释是否只因好想起来而被高估。用户说"先查哪个"走本模型；用户说"最近老看到这类事，是不是很常见"走易得性启发。

与[第一性原理](../first-principles/SKILL.md)：已经有几个假说要排序，走本模型；现有假说都建在行业类比上、需要拆地基重建，走第一性原理。
与[溯因推理](../../thinking-models/abductive-reasoning/SKILL.md)：奥卡姆排序已有解释；溯因先产表再可比。
