# 两分钟法则 Two-Minute Rule

## 这是什么

**两分钟法则**：在处理收件箱/澄清时，若下一步行动**确实**能在约两分钟内完成，则立即做掉，而不是记入清单。目标是减少「登记成本 > 执行成本」的琐事堆积。

它是 GTD 澄清阶段的**局部启发式**，不是全天工作法，更不是把大事拆成假两分钟。

## 什么时候用

- "收件箱里一堆小回复"
- "两分钟法则 / 要不要记下来"
- 澄清待办时犹豫「记还是做」

**不要**当主模型：

- 重建整套收集-澄清-组织 → [`gtd`](../gtd/SKILL.md)
- 今天最难的大事 → [`eat-the-frog`](../eat-the-frog/SKILL.md)
- 保护深度块不被琐事侵蚀 → [`time-blocking`](../time-blocking/SKILL.md) / [`deep-work`](../../learning-growth/deep-work/SKILL.md)

## 怎么用（执行步骤）

1. **处于澄清上下文。** 正在处理收集箱；不是在深度块中间。
2. **诚实估时。** 问：现在动手，两分钟内能到「完成」？含找到文件/打开系统的时间。
3. **是 → 立即做完并勾掉。** 不做「先记再做」。
4. **否 → 写成下一步并组织。** 委派/排程/项目；见 GTD。
5. **防止滥用。** 一天两分钟事项过多时，改 [`batching`](../batching/SKILL.md) 窗口，避免伪两分钟打断深度。
6. **深度块内默认关闭。** 块内出现的两分钟冲动记入清单，块后再澄清。

## 例证

**邮件**：「确认收到，周五交」→ 两分钟回掉——揭示登记成本高于回复。

**误用**：把「写报告」骗成两分钟开头——揭示法则只管真正短闭环。

## 什么时候不适用（边界）

- **高认知连续块中**：先记下，勿打断。
- **估时总失真**：先练拆任务，不硬套两分钟。
- **团队流程需留痕**：即使两分钟也要按 SOP 记录 → [`checklist-sop`](../checklist-sop/SKILL.md)。

## 常见误用

- **把开始两分钟当完成**：未闭环仍须进系统。
- **用两分钟逃避青蛙**：难事先做。
- **全天到处两分钟**：粉碎专注 → 批处理。
- **替代 GTD 回顾**：法则只是澄清插件。

## 相关模型

- **与[GTD](../gtd/SKILL.md)**：本法则嵌在澄清步；完整可信系统仍靠 GTD。
- **与[批处理](../batching/SKILL.md)**：大量短任务宜批，不宜散落两分钟。
- **与[吃掉那只青蛙](../eat-the-frog/SKILL.md)**：难事先于琐事。
- **与[委派](../delegation/SKILL.md)**：两分钟内你能做但他人更合适 → 仍可委派（看机会成本）。
- **若用户指的是「把新习惯缩到两分钟就开始」**（James Clear《原子习惯》）：那是习惯启动启发式，不是本条，走 [`fogg-behavior-model`](../../thinking-models/fogg-behavior-model/SKILL.md)。

## 记忆钩子

澄清时：**两分钟内能完就做掉**；否则写下，别骗自己。
