# 结构化思维 Structured Thinking

## 这是什么

**结构化思维**：面对复杂或模糊问题时，用显式结构管理认知负荷——先定义要回答的问题，再选拆解方式，分层分析，最后综合成可辩护结论与下一步。它是**元流程**，不是单一模板。

常见部件（仓库内多有专条）：问题定义（可接 SCQA）、分类纪律（MECE）、逻辑树、论证表达（金字塔）、检验（假设检验）。本 Skill 负责**何时用哪一步、如何串起来**。

## 什么时候用

- "这个问题太大/太乱，不知道从哪开始"
- "讨论发散，需要一个分析骨架"
- 直接说结构化思维 / 把问题结构化

**不要**当主模型（应直达专条）：

- 用户明确只要不重不漏拆分类 → [`mece`](../mece/SKILL.md)
- 用户只要汇报结论塔 → [`pyramid-principle`](../pyramid-principle/SKILL.md)
- 用户只要开场 SCQA → [`scqa`](../scqa/SKILL.md)
- 用户只要逻辑树画法 → [`logic-tree`](../logic-tree/SKILL.md)

## 怎么用（执行步骤）

1. **问题定义（一句）。** 「我们要回答什么？成功标准是什么？边界外是什么？」可用 SCQA 的 Q。判据：两人独立复述是否一致。
2. **选择主结构。** 常见：议题树/逻辑树、时间线、利益相关方、公式拆解、对比选项。一次一个主轴；写明为何选它。
3. **拆解并贴 MECE 检查。** 调用 MECE 纪律：同层不重不漏（相对边界）。每个叶子变成可分析问题或数据需求。
4. **分析叶子，标置信度。** 每叶：证据、假设、未知。禁止空叶子直接变结论。
5. **综合向上。** 用「所以什么？」把叶子收成对主问题的答案；需要沟通时再用金字塔包装。
6. **下一步与证伪。** 列出关键未知与验证动作（可接假设检验）。结构服务决策，不是画完就停。

## 例证

**营收下滑**：定义「未来两季如何止跌」→ 利润/收入树拆解 → 各叶证据 → 综合「价量哪个主因」→ 验证计划。揭示：结构把「大家觉得」变成可分工问题。

**失败结构**：漂亮框架但主问题每周改——揭示步骤 1 不稳则下游全废。

## 什么时候不适用（边界）

- **纯执行清单已清晰**：不要为了「显得结构化」再造树。
- **需要深度发散创意**：先水平思考/六帽，再结构化收敛。
- **紧急人身安全**：先行动后复盘结构化。

## 常见误用

- **结构炫技**：框架比结论还长 → 以主问题为尺子裁剪。
- **过早冻结树**：探索期强行 MECE → 先发散再结构。
- **与专条抢戏**：用户说 MECE/金字塔/SCQA 专名 → 走专条。

## 相关模型

- **与[MECE](../mece/SKILL.md)**：MECE 是本流程拆解步的纪律插件。
- **与[逻辑树](../logic-tree/SKILL.md)**：逻辑树是本流程常用的显式载体。
- **与[金字塔原理](../pyramid-principle/SKILL.md)**：金字塔管对外表达；本模型管对内分析路径。先结构化想清楚，再金字塔写出。
- **与[SCQA](../scqa/SKILL.md)**：SCQA 钉读者问题；可作为步骤 1 的工具。
- **与[批判性思维](../critical-thinking/SKILL.md)**：结构产出的结论仍要按证据标准审。

## 记忆钩子

先问清问题，再选一把尺子拆开，最后收成一句可辩护的答案。
