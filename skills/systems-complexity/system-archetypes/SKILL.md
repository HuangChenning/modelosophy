# 系统基模 System Archetypes

## 这是什么

**系统基模**：一组反复出现的**反馈结构故事**（如增长上限、舍本逐末、恶性竞争、目标侵蚀、公地悲剧变体等）。每个基模指定：关键变量、增强/调节回路如何咬合、常见误干预、高杠杆改法。

它是**模式识别助手**：先匹配结构，再谈对策；不是标签收藏。

## 什么时候用

- "怎么老是短期修好长期更糟"
- "增长突然顶住了 / 竞争对手互相加码"
- "系统基模 / fixes that fail / limits to growth"

**不要**当主模型：
- 还没变量就要画回路 → 先 [`causal-loop-diagram`](../causal-loop-diagram/SKILL.md)
- 要定量存量流量 → [`stock-and-flow`](../stock-and-flow/SKILL.md)
- 只要文化分层 → [`iceberg-model`](../iceberg-model/SKILL.md)

## 怎么用（执行步骤）

1. **写症状时间线。** 「先变好再变坏」「增长后平台」「双方加码」等。判据：有时间顺序，不是静态抱怨。
2. **候选 1–2 个基模。** 对照经典：增长上限、舍本逐末（症状解 vs 根本解）、恶性竞争、目标侵蚀、富者愈富等。判据：能指出「哪条是增强、哪条是延迟调节」。
3. **落到具体变量。** 把基模槽位填成你的变量名（库存、士气、补丁次数）。判据：外人能据图复述故事。
4. **标出当前干预落在哪。** 是否在「症状解」上加码？判据：标出正在强化的回路。
5. **选结构级动作。** 基模建议通常是：减弱症状解依赖、加强根本解、改变目标/激励、削弱军备竞赛耦合。判据：动作改回路结构，而非再加同层补丁。
6. **设监测。** 选 1–2 个延迟指标，防止「又修好了其实在欠债」。

## 例证

**加班救火（舍本逐末）**：短期加人救缺陷 → 根本设计债未还 → 更依赖加班。揭示：症状解挤出根本解。

**增长上限**：获客增强回路撞上支持容量调节回路——继续砸广告是低杠杆。

**（原书卡片）**：若只列基模名称无变量，优先完成步骤 3。

## 什么时候不适用（边界）

- **一次性事故**：先事件分析，勿硬套基模。
- **数据与因果极弱**：先澄清变量，再命名基模。
- **纯优化排程**：关键路径/看板可能更直接。

## 常见误用

- **贴标签替代画图**：必须填变量。
- **把基模当宿命**：结构可改。
- **与冰山混淆**：冰山是文化/假设层；基模是动态结构故事。

## 相关模型

- **与[因果回路图](../causal-loop-diagram/SKILL.md)**：CLD 是画法；基模是可复用模板。先画后贴标签更稳。
- **与[杠杆点](../leverage/SKILL.md)**：基模提示杠杆在哪一类结构改动；Meadows 层级提供干预深度语言。
- **与[反馈回路](../../systems-classic-effects/feedback-loops/SKILL.md)**：反馈回路讲增强/调节基本件；基模是其组合故事。
- **与[二阶思维](../../systems-classic-effects/second-order-thinking/SKILL.md)**：二阶问后果的后果；基模提供常见「二阶变糟」结构。

## 记忆钩子

先匹配时间线上的「修好→更糟 / 增长→撞墙」，再填变量——标签跟在结构后面。
