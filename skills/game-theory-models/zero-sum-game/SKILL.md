# 零和博弈 Zero-Sum Game

## 这是什么

**一方所得精确等于他方所失（支付和为常数，常为 0）。**

von Neumann 矩阵博弈核心设定：利益严格对立，无共同增益。适用竞技、份额争夺等；误用于可做大蛋糕的协作会把伙伴当敌人。常与最小最大/混策略解一起出现。

## 什么时候用

用户出现以下意图时启用本 Skill：

- "这是不是零和博弈"
- "蛋糕就这么大"
- "一方赢必有一方亏同等"

**不要**在以下情况套用本模型：

- 合伙做大市场 → ../positive-negative-sum-game/SKILL.md
- 要算最优防御混合 → ../minimax-theorem/SKILL.md
- 只是口号式“人生如棋” → ../game-theory/SKILL.md 先建模

## 怎么用（执行步骤）

1. **写各方支付并求和。** 每个结果格各方收益之和是否近似常数？是 → 零和（或常和）候选。
2. **区分会计零和与真实零和。** 市场份额常近零和，但行业总利润、创新可正和——分开写“争什么”。
3. **若确认零和，禁用双赢空话。** 分析焦点转为相对优势、混策略、信息；合作话术只在改变博弈（扩大蛋糕）时有意义。
4. **输出定性。** 零和 / 常和 / 正和 / 负和之一 + 依据一行。

## 例证

**网球局点**：一分你得我失。揭示严格对抗、适合最小最大思维。

**固定预算招标**：合同总额固定时份额近零和；若可提高总预算则结构变。揭示先问变量是否固定。

## 什么时候不适用（边界）

- **误贴标签**：多数商业同时含份额争夺与增量创造；勿一刀切。
- **伦理**：不协助零和化欺诈或违法串谋。

## 常见误用

- **把竞争口头说成零和**：先核支付和；可能是正和竞争。
- **在零和里谈默契涨价**：可能违法；本 skill 不给串谋方案。

## 相关模型

- **与[正和与负和博弈](../positive-negative-sum-game/SKILL.md)**：总量可变时走对方。
- **与[最小最大定理](../minimax-theorem/SKILL.md)**：确认零和后求稳健值走对方。

## 记忆钩子

和为常，才叫零和；先加总再贴标签。
