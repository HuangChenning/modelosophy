# 清单与 SOP Checklist / SOP

## 这是什么

**清单 / SOP**：把重复性高、遗漏代价高的工作拆成可勾选的关键步骤（或书面标准作业），在执行点强制对照。目标是对抗记忆失效与熟练后的疏忽，统一「怎样算做对」。

清单偏**关键点核对**；SOP 偏**完整标准流程**。二者同属外部化程序记忆。

## 什么时候用

- "上线总漏步骤"
- "SOP / checklist / 标准作业"
- 交接、安全、合规、手术级操作

**不要**当主模型：

- 尚无稳定流程的探索 → 先实验/MVP（决策类）或敏捷小步
- 要找多因根因 → [`five-whys`](../../cognitive-thinking-tools/five-whys/SKILL.md)
- 持续改进循环设计 → [`pdca`](../pdca/SKILL.md) / [`continuous-improvement`](../continuous-improvement/SKILL.md)

## 怎么用（执行步骤）

1. **界定适用场景。** 重复 + 遗漏代价高；写出触发条件（「每次发布前」）。
2. **只列关键步骤。** 5–9 项优先；每项可观察「做了/没做」。删掉正确也会做的废话。
3. **区分 DO-CONFIRM 与 READ-DO。** 熟练流程用「做完再核对」；高风险生疏用「读一步做一步」。
4. **放置在执行点。** 清单出现在操作现场/发布按钮旁，不进无人读的 wiki 坟场。
5. **修订权与版本。** 谁可改、改后如何培训；用一次失败驱动改清单（连 PDCA）。
6. **停用条件。** 流程已变或清单变形式主义 → 重写或废止，禁止为合规演戏。

## 例证

**手术安全清单**：麻醉前/切皮前/离开前核对——揭示专家也需要外部核对。

**发布 Checklist**：迁移、开关、回滚负责人——揭示降低「以为做过了」。

## 什么时候不适用（边界）

- **高度新颖无步骤可循**：先探索再固化。
- **清单长到无人用**：砍到关键少数。
- **惩罚导向勾选**：导致造假；要心理安全。

## 常见误用

- **写成小说级 SOP**：没人读。
- **有清单无停机权**：发现问题不能喊停=摆设。
- **用清单替代训练**：新手仍需带教。
- **永不更新**：与真实流程脱节。

## 相关模型

- **与[PDCA](../pdca/SKILL.md)**：清单失败→Check/Act 修订清单。
- **与[持续改进](../continuous-improvement/SKILL.md)**：SOP 是改进的载体之一。
- **与[5S](../five-s/SKILL.md)**：现场整洁支撑清单可执行。
- **与[5Why](../../cognitive-thinking-tools/five-whys/SKILL.md)**：重复遗漏先清单；深层为何缺清单用五问。
- **与[委派](../delegation/SKILL.md)**：委派时附 SOP/完成定义。

## 记忆钩子

专家更需要清单——**关键步骤外置，勾完再走**。
