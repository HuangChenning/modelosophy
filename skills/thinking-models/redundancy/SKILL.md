# 冗余备份 Redundancy

## 这是什么

冗余（redundancy）指：**故意保留超出“刚好够用”的资源、通路或信息副本**，以便在部件失效、误差累积或负载尖峰时，系统仍能完成关键功能。工程上常见：N+1 备机、异地灾备、多重传感器表决、纠错码、双人复核。

关键细分：

- **同质冗余**：多份相同部件（便宜，但共因故障可一锅端）；
- **多样冗余**：不同设计/供应商/算法实现同一功能（贵，抗共因）；
- **时间/信息冗余**：重试、校验和、备份快照。

它回答的是**“坏了还能不能转”**，不是“波动会不会让你更强”。

## 什么时候用

- 关键业务不能停、数据不能丢、安全不能赌单点；
- 发现单点故障（SPOF）或“全押一条路径”；
- 直接提冗余 / 备份 / 双活 / N+1 / 容错。

**不要**当主模型：
- 目标是从波动中获益、杠铃与可选性 → [`antifragility`](../antifragility/SKILL.md)；
- 画存量流量与反馈回路 → [`systems-thinking`](../../systems-classic-effects/systems-thinking/SKILL.md)；
- 找投入产出极度不均的少数杠杆 → [`pareto-principle`](../../systems-classic-effects/pareto-principle/SKILL.md) 或 [`leverage`](../leverage/SKILL.md)。

## 怎么用（执行步骤）

1. **定义不可接受的失效。** 什么功能必须在故障下仍可用？RTO/RPO、人身安全、合规底线写清。
2. **画出单点。** 人、机、供应商、机房、密钥、唯一专家——任一失效即全停的点列清单。
3. **选冗余类型。** 同质副本 vs 多样实现；热备/温备/冷备；按失效模式选，而不是“多买一台就完事”。
4. **算成本与共因。** 冗余有持有成本；同质冗余挡不住同一软件 bug / 同区域停电。对共因单独加压测。
5. **演练切换。** 未演练的备份等于没有。定期故障注入或桌面推演，验证切换时间 ≤ 目标。

## 例证

**飞机多套液压/飞控**：多样与多重通道降低单点机械失效——揭示**关键功能的有意多余**。

**RAID / 异地备份**：磁盘冗余挡硬件坏；挡不了勒索软件同步加密——揭示**同质副本的共因边界**，需离线/不可变备份。

**（原书卡片）备份思维 / 不要单点**：方向正确；家庭多收入源例可用。但卡片把 Google 20% 时间、华为「耗散」创新预算也叫冗余，并把冗余收成「提高反脆弱性」——**概念偷换**：探索预算/可选性更靠近反脆弱与机会组合，不等于可靠性工程里的备份。须坚持：冗余 ≠ 反脆弱，也 ≠ 无限制堆预算。

## 什么时候不适用（边界）

- **失效可接受且成本敏感**：创业探索期过度灾备会拖死现金。
- **共因未消除时堆同质副本**：制造虚假安全感。
- **把冗余当反脆弱**：多备几台服务器不会让你“从宕机中变强”，只是更强韧/可恢复。
- **监管或伦理禁止的双重记账式“冗余”**：不在本模型范围。

## 相关模型

- **与[反脆弱](../antifragility/SKILL.md)**：冗余≈提高强韧/可恢复；反脆弱要设计不对称获益。需要“坏了还能转”用本模型；需要“波动喂胖我”用反脆弱。
- **与[系统思维](../../systems-classic-effects/systems-thinking/SKILL.md)**：系统图帮找单点与延迟；冗余是对关键链路的设计处方之一。
- **与[杠杆](../leverage/SKILL.md)**：杠杆放大行动效果；冗余常降低脆弱性但也可能降低效率——在关键节点上权衡。
