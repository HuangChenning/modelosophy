# 抽象阶梯 Ladder of Abstraction

## 这是什么

**抽象阶梯**：同一主题可以在不同**抽象高度**上谈论——底层接近可观察的具体事物与操作，上层是范畴、原则、口号。Hayakawa 用梯子比喻：爬得越高，包含越广、细节越少；待在错误高度会让人「鸡同鸭讲」（一方要指标，一方只给愿景）。

本模型的动作是**有意识地上下钻**：该决策落地时下钻到可操作层；该对齐方向时上钻到共同范畴——并标明你当前站在哪一级。

**≠ 推论阶梯（Ladder of Inference）**：后者是「资料→含义→假设→结论→信念」的推理攀升；本模型是「具体↔抽象」的语义高度。

## 什么时候用

- "讨论太虚/太碎，对不齐"
- "把战略翻译成可执行动作"或反过来"从一堆细节抽出原则"
- 直接说抽象阶梯 / ladder of abstraction / 上钻下钻
- 写作、教学、需求澄清需要控制抽象度

**不要**当主模型：

- 争论「我们是不是把假设当成事实」→ [`ladder-of-inference`](../../thinking-models/ladder-of-inference/SKILL.md)
- 整段论证的证据标准 → [`critical-thinking`](../critical-thinking/SKILL.md)
- 问题拆成树 → [`logic-tree`](../logic-tree/SKILL.md) / [`mece`](../mece/SKILL.md)

## 怎么用（执行步骤）

1. **写出当前句子，并标高度。** 高：范畴/原则/口号；中：类型/流程名；低：可观察事例、数字、步骤。判据：能否指出至少一例「可拍照/可计数」的底层对应物？若不能，多半偏高。
2. **定目标高度。** 决策/执行会 → 需要低层；对齐目的/选框架 → 允许中高层。写一句：「本次对话要停在 ____ 层。」
3. **下钻（抽象→具体）。** 对每个高层词问：举例？谁？何时？度量？禁止用另一个同级抽象词回答（「提升体验」≠「优化服务」）。判据：出现可验证描述。
4. **上钻（具体→抽象）。** 对一堆事例问：它们共享什么关系/范畴？上钻后的标签必须能覆盖已列事例且排除明显无关项。判据：能否指出一个**反例**仍不属于该标签。
5. **同层对齐检查。** 会议中若一人在愿景层、一人在工单层，先喊停并约定共同高度，再继续；必要时双轨：上钻对齐目的，下钻对齐动作。
6. **防空转。** 高层结论要挂至少一条低层锚；低层清单要挂「所以什么」的上层意义，否则只是流水账。

## 例证

**「数字化转型」会议**：高层口号无法排期 → 下钻到「本季度哪三个流程上线、成功指标是什么」。揭示：战略词必须能落到可验证动作。

**客服工单堆砌**：全是个案 → 上钻到「三类重复缺陷模式」再分配改造。揭示：具体层有信息，但决策需要中层范畴。

**（原书卡片）**：若只画梯子示意图而无上下钻判据，易变成装饰；以「能否举例/能否反例」为操作标准。

## 什么时候不适用（边界）

- **诗歌/隐喻故意含混**：艺术表达可不钉高度。
- **数学形式系统**：抽象层级由定义约束，不靠日常语义梯子。
- **已在错误问题**：高度调对也救不了问错题——先问题定义（[`scqa`](../scqa/SKILL.md)）。

## 常见误用

- **与推论阶梯混淆**：说「抽象阶梯」却在查信念跳跃 → 改走 ladder-of-inference。
- **用抽象逃责**：「我们要卓越」当计划 → 强制下钻。
- **假下钻**：用同级黑话替换 → 要求可观察锚点。
- **过早上钻丢掉反例**：概括吃掉异常 → 异常单独建桶或回到低层。

## 相关模型

- **与[推论阶梯](../../thinking-models/ladder-of-inference/SKILL.md)**：**硬区分。** 推理路径/信念攀升 → 推论阶梯；表述具体↔抽象高度 → 本模型。
- **与[金字塔原理](../pyramid-principle/SKILL.md)**：金字塔要求上层概括下层；抽象阶梯提供「这一层算不算真概括」的高度感。
- **与[MECE](../mece/SKILL.md)**：上钻出的类别应尽量不重不漏。
- **与[结构化思维](../structured-thinking/SKILL.md)**：总流程中可随时调用本模型校准讨论高度。
- **与[概念图](../concept-map/SKILL.md)**：概念图标关系命题；抽象阶梯校准节点该写多「虚」。

## 记忆钩子

话太虚就下钻到能指；话太碎就上钻到能判——先约定站在哪一级。
