# 里程碑规划 Milestone Planning

## 这是什么

**里程碑规划**：在时间线上设置少量**可验证的阶段门**（有完成定义、可演示/可验收），用它们对齐范围、依赖与沟通，而不是用密密麻麻任务冒充计划。里程碑是「到了什么状态」，不是「忙了多久」。

它是**阶段成果层**；甘特/关键路径是任务与依赖层；OKR 是目标与关键结果层（战略类）。

## 什么时候用

- "大项目只有截止日期没有中间门"
- "里程碑 / 版本节点 / 阶段验收"
- 跨团队需要对齐「何谓完成」

**不要**当主模型：

- 画条形图与依赖细排 → [`gantt-chart`](../gantt-chart/SKILL.md)
- 算最长工期链 → [`critical-path`](../critical-path/SKILL.md)
- 公司目标与 KR → [`okr`](../../strategy-competition/okr/SKILL.md)

## 怎么用（执行步骤）

1. **写最终验收图像。** 一句话：谁在何时能看到什么结果。
2. **倒推 3–7 个里程碑。** 每个有日期或窗口 + Done 标准（可测/可演示）。
3. **检查价值增量。** 每个里程碑最好交付可检视增量，避免「全在最后集成」。
4. **标出跨里程碑依赖与责任人。** 依赖不清则门会假绿。
5. **缓冲与杀伤半径。** 高不确定段加缓冲；延误时砍范围保门，或显式移门。
6. **回顾门质量。** 门到了却无法验收 → 重写 Done，而非只改日期。

## 例证

**产品**：Alpha 可用 / Beta 对外 / GA——揭示阶段门沟通语言。

**论文**：开题通过 / 数据锁定 / 初稿 / 答辩——揭示学术亦可里程碑化。

## 什么时候不适用（边界）

- **纯探索无承诺日期**：用学习里程碑（「验证假设 X」）而非假交付门。
- **单人两日小任务**：过度设计。
- **政治性假里程碑**：只报喜不验收 → 先修治理。

## 常见误用

- **里程碑=状态会议日期**：无 Done。
- **门太多**：变成微型任务列表。
- **只移日期不砍范围**：计划漂移。
- **与 OKR 混用为同一物**：OKR 管目标意图；里程碑管阶段交付。

## 相关模型

- **与[甘特图](../gantt-chart/SKILL.md)**：里程碑定门；甘特展开任务条。
- **与[关键路径](../critical-path/SKILL.md)**：门之间的最长链决定能否按期。
- **与[OKR](../../strategy-competition/okr/SKILL.md)**：OKR 答「为何/何成果」；里程碑答「何时过哪一关」。
- **与[敏捷迭代](../agile-iteration/SKILL.md)**：迭代是短节奏；里程碑可跨多个迭代。
- **与[计划谬误](../../decision-probability/planning-fallacy/SKILL.md)**：估里程碑时加参考类预测。

## 记忆钩子

里程碑是**可验收的门**，不是日历上的彩旗。
