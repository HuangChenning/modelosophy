# 复盘四步法 After Action Review

## 这是什么

**After Action Review（AAR）**：在一次行动/迭代结束后，由参与者按固定节奏回答四问——**我们原打算做什么？实际发生了什么？为何有落差？下次具体改什么？**——把经验变成可执行的规则、检查项或实验，而不是感想分享会。

核心纪律：**对事不对人、证据优先、产出可检查的改进行动**。

## 什么时候用

- "项目/战役/发布结束后做 AAR / 复盘"
- "计划与结果不一致，想提炼教训"
- "迭代节奏里固定回顾"
- 有明确意图与可观察结果的团队行动

**不要**当主模型：

- 尚未执行、要挖潜在失败 → [`pre-mortem`](../pre-mortem/SKILL.md)
- 个人判断校准、要前瞻记录 → [`decision-journal`](../decision-journal/SKILL.md)
- 需要独立攻击式找漏洞 → [`red-team`](../red-team/SKILL.md)
- 单一故障要因果链深挖 → [`five-whys`](../../cognitive-thinking-tools/five-whys/SKILL.md)（可嵌在第 3 步）

## 怎么用（执行步骤）

1. **设定安全与范围。** 宣布：目标是改进系统，不公开羞辱。框定时间盒与议题边界（一次发布/一次演练）。
2. **意图：原计划是什么？** 对照文档/决策日志：目标、成功标准、关键假设、资源与约束。禁止事后改写「其实我们想的是…」。
3. **事实：实际发生了什么？** 时间线、数据、外部事件。先事实后解释；争议处标「待核」。
4. **落差：为什么一样/不一样？** 分维持项与改进项；对关键落差用证据，避免甩锅。可局部调用五问。
5. **行动：下次改什么？** 每条改进：负责人、截止、如何验证。无主的「我们要加强沟通」删除或改写。
6. **入库与关闭。** 把改进行动写入下一迭代计划/清单；跟踪上次 AAR 条目是否兑现。

## 例证

**军事/应急演练（经典）**：对照任务命令与实际机动，改通联与集合点。揭示：AAR 的力量在**短反馈 + 无责文化**。

**产品发布**：转化低于预期；事实显示支付链路超时。行动：超时监控与降级方案进门控。揭示：落差要落到机制，不是「市场不行」空话。

**个人项目**：原定两周交付，实际四周；落差指向范围蔓延。行动：下迭代强制 MVP 范围冻结。揭示：可与 [`mvp`](../mvp/SKILL.md) / [`planning-fallacy`](../planning-fallacy/SKILL.md) 连用。

## 什么时候不适用（边界）

- **文化只有追责**：产出谎言 → 先换主持人或外请中立引导。
- **无可观察结果**：还在空转讨论 → 先定义指标再行动。
- **替代战略分析**：AAR 不自动产生新战略选项。

## 常见误用

- **开成庆功/批斗**：破坏心理安全。
- **跳过「意图」直接聊感觉**：无法对照。
- **改进无主人无验证**：等于没复盘。
- **与事前验尸混淆**：验尸在事前；AAR 在事后。

## 相关模型

- **与[事前验尸](../pre-mortem/SKILL.md)**：**硬区分。** 验尸用「已失败」生成预防；AAR 用「已发生」提炼教训。可连用：验尸清单作 AAR 对照表。
- **与[决策日志](../decision-journal/SKILL.md)**：日志提供「当时意图与预测」；AAR 消费这些记录避免假记忆。
- **与[OODA](../ooda-loop/SKILL.md)**：OODA 是节奏闭环；AAR 是环末的结构化学习插入点。
- **与[红队](../red-team/SKILL.md)**：红队偏独立对抗；AAR 偏全体学习。安全关键系统两者都要。
- **与[5Why](../../cognitive-thinking-tools/five-whys/SKILL.md)**：AAR 第 3 步可嵌入五问，但整场不要变成只挖一个根因。

## 记忆钩子

四问：**打算 → 实际 → 为何 → 下次**；没有「下次谁在何时验证」，就只是聊天。
