# 关键路径 Critical Path Method

## 这是什么

**关键路径**：在带依赖的任务网络中，从开始到结束**工期最长**的那条链路；其上任务总时差为零（或最小）——延迟一天，项目往往延迟一天。CPM 用于识别必须盯紧的任务、可并行的任务与缓冲放置。

## 什么时候用

- "项目总延期，不知道哪项最致命"
- "关键路径 / CPM / 依赖链工期"
- 有明确交付日与多任务依赖的项目

**不要**当主模型：

- 团队持续流动 → [`kanban`](../kanban/SKILL.md)
- 不确定需求短迭代 → [`agile-iteration`](../agile-iteration/SKILL.md)
- 个人事务系统 → [`gtd`](../gtd/SKILL.md)

## 怎么用（执行步骤）

1. **列出任务与依赖。** 每项：前置、工期估计、负责人。禁止遗漏外部依赖。
2. **画网络（节点或箭头）。** 确认无环；标清并行枝。
3. **正推最早时间、逆推最晚时间。** 计算总时差；时差≈0 的链即关键路径候选。
4. **验证估计。** 对关键任务工期做风险加权；假精确的一天会误导。
5. **管理动作。** 压缩关键任务、加资源、拆并行；非关键任务避免乱加塞抢资源。
6. **动态维护。** 任一项完成/延期后重算关键路径——它会移动。

## 例证

**活动策划**：场地确认→物料印刷→布置，印刷在关键路径上——揭示催非关键的彩排救不了工期。

**软件发布**：合规审批在关键路径——揭示工程燃尽不解决审批等待。

## 什么时候不适用（边界）

- **任务不可分、依赖未知的探索工作**：先迭代学习。
- **工期估计完全拍脑袋且无修正**：先改善估计。
- **单一任务无网络**：无需 CPM。

## 常见误用

- **把所有任务当关键**：失去聚焦。
- **忽视资源冲突**：两条「可并行」实际抢同一人 → 资源关键链。
- **算一次永不动**：路径会变。
- **用 CPM 反对敏捷**：工具场景不同。

## 相关模型

- **与[看板](../kanban/SKILL.md)**：流动优化 vs 项目网络工期。
- **与[TOC](../../cognitive-thinking-tools/theory-of-constraints/SKILL.md)**：约束可能在资源；可与关键链思想连用。
- **与[PDCA](../pdca/SKILL.md)**：重算与复盘；估计偏差在 Check 中显式记录并加缓冲。
- **与[艾森豪威尔](../eisenhower-matrix/SKILL.md)**：紧急重要≠关键路径；关键是网络概念。
- **与[敏捷迭代](../agile-iteration/SKILL.md)**：不确定探索优先迭代；依赖清晰交期项目用 CPM。

## 记忆钩子

盯**最长依赖链**；非关键再忙也救不了项目完工日。
