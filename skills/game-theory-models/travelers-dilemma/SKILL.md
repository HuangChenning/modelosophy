# 旅行者困境 Traveler's Dilemma

## 这是什么

**双方申报损失金额，低报者得利机制把理性推向最低——但实验常报更高。**

Basu：航空公司赔付规则使略低申报更优，迭代优势把纳什推到下限；类似囚徒但策略连续/多档。实验申报远高于纳什。揭示迭代理性的描述局限与“一点点好处”的诱惑结构。

## 什么时候用

用户出现以下意图时启用本 Skill：

- "旅行者困境"
- "报高了被对方低报捅"
- "规则是不是逼大家往低走"

**不要**在以下情况套用本模型：

- 两策略招供沉默 → ../prisoners-dilemma/SKILL.md
- 设计更好赔付规则 → ../mechanism-design/SKILL.md
- 拍卖规则 → ../auction-theory/SKILL.md

## 怎么用（执行步骤）

1. **写申报区间与奖励/惩罚参数。** 确认“略低者奖励、高者惩罚”结构。
2. **做迭代优势直觉。** 从最高往下削，看是否沉底。
3. **对照行为预期。** 人们会停在哪一档？参数（奖励大小）是否改变。
4. **改规则选项。** 缩小奖励、改匹配支付。输出：纳什底 + 行为带 + 改参建议。

## 例证

**Basu 旅行者**：理性下限 vs 高申报实验。揭示理论—行为裂口。

**某些绩效相对考核**：略低于同事得分机制引发竞相压低。

## 什么时候不适用（边界）

- **参数敏感**：奖励很小时行为更远离纳什。
- **与囚徒关系**：同属社会困境族，策略空间不同。

## 常见误用

- **直接当囚徒讲完**：要保留多档迭代结构。
- **用其教人钻空子伤害集体**：分析可，不协助损人。

## 相关模型

- **与[囚徒困境](../prisoners-dilemma/SKILL.md)**：离散两策略近亲。
- **与[机制设计](../mechanism-design/SKILL.md)**：改赔付规则。
